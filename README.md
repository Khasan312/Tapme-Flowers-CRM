# Tapme Flowers

CRM для цветочных магазинов: Django REST Framework + PostgreSQL, React/TypeScript,
Celery + Redis. Исходный дизайн `tapme-flowers-v1.html` сохранён.

Интерфейс перенесён по структуре макета: общий поиск, разделы настроек,
плитки и задачи заказов, страницы клиентов, напоминания и доставка по окнам.
[Сверка и снимки](docs/design-audit/README.md).
Сначала прочитайте [SESSION_HANDOFF.md](SESSION_HANDOFF.md), если продолжаете работу.
Правила Git для команды, PR, релизы и hotfix: [CONTRIBUTING.md](CONTRIBUTING.md).

Реализованы заказы от приёма до вручения, рабочие экраны флориста и курьера,
ручной учёт оплат и возвратов, приватные фото, клиенты и получатели, прайс,
напоминания, отзывы/жалобы, настройки магазина и сотрудники. Все экраны работают
с API. Бизнес-правила и сценарии используют Python-контракты вместо Django ORM.

## Филиалы

У одной компании может быть несколько филиалов: **Настройки → Точки → Добавить
точку**. Укажите название, адрес, контакты и свои окна доставки с ценой/лимитом.
Когда доступно больше одной точки, нажмите **название магазина внизу бокового меню**
и выберите филиал или **Все точки**. Выбор сохраняется в адресе и после обновления страницы.
Архивные филиалы не предлагаются для новых заказов; «Все точки» сохраняет
доступ к их истории, даже если остался один активный филиал.

- Заказы, доставки, календарь, задачи и сводка переключаются вместе с точкой;
  в общем режиме заказы и доставки подписаны названием филиала. В форме нового
  заказа выбирается точка, окна/стоимость/вместимость берутся из её настроек.
- Очередь напоминаний и её счётчики тоже разделены. При формировании точка берётся
  из последнего неотменённого заказа клиента (по времени создания), а для клиента
  без заказов — основная. Сценарий «После доставки» относится к точке вручённого
  заказа. Сформированное напоминание сохраняет свою точку; рассылка и ограничения
  частоты сообщений остаются общими для клиента в компании.
- Клиенты, их контакты и прайс общие. Суммы/история заказов в карточке клиента
  учитывают выбранные доступные точки. Настройки сценариев и шаблоны общие;
  существующий WhatsApp-канал и переписка пока тоже общие на компанию.
- Владелец видит все точки. В редакторе сотрудника он назначает доступные точки
  отдельной кнопкой «Сохранить доступ к точкам». Пустой набор менеджера означает все точки;
  флористу/курьеру нужно назначение. Прежние флористы/курьеры привязаны к основной.
- Основную точку и филиал с незавершёнными заказами архивировать нельзя.
  Архивирование сохраняет историю; она доступна в режиме «Все точки».
- Название компании/часовой пояс и контакты основной точки остаются во вкладке
  «Магазин». Окна доставки выбранного филиала можно менять и во вкладке
  «Окна доставки». QR для оплаты настраивается для выбранной точки в «Каналах».

Это реализация основных филиалов. Целевое ТЗ `docs/spec/01-multi-point.md` шире:
зоны доставки, структурированное расписание по дням, перенос заказов, распределение
чатов и букетов дня по точкам пока не реализованы.

## Запуск существующего окружения

На текущем компьютере `.env` уже настроен. Логин **owner**, локальный пароль —
значение `TAPME_BOOTSTRAP_PASSWORD` в `.env`. Это владелец своего бизнеса,
не глобальный администратор Django. Если пароль изменён в интерфейсе, используйте
новый: bootstrap-переменная не меняет пароль существующей учётной записи.

```bash
docker compose --profile app build api
docker compose --profile app run --rm api python manage.py migrate
docker compose --profile app --profile jobs up -d --wait
cd frontend
npm ci
npm run dev
```

Открыть в Firefox: [http://127.0.0.1:5173](http://127.0.0.1:5173).
API: [проверка готовности](http://127.0.0.1:8000/health/),
[Swagger после входа](http://127.0.0.1:8000/api/docs/).
При изменении backend повторите сборку и `up` обоих профилей, чтобы обновились
API, worker и beat. Vite автоматически подхватывает изменения frontend.

Для первого запуска на другом компьютере создайте `.env` из `.env.example`,
задайте собственные `POSTGRES_PASSWORD`, `DJANGO_SECRET_KEY` и
`TAPME_BOOTSTRAP_PASSWORD`, выполните сборку/миграции, затем:

```bash
docker compose --profile app run --rm api python manage.py bootstrap_business --name 'Tapme Flowers' --username owner
```

Команда не перезаписывает существующий пароль. Создание второго независимого
магазина выполняется той же командой с другим названием и логином владельца.
Сотрудники создаются владельцем в «Настройках»; там же роли, блокировка доступа,
сброс пароля и удаление сотрудника из магазина. Удаление требует подтверждения:
доступ закрывается, история заказов и оплат сохраняется. Незавершённые назначения
нужно сначала передать другому сотруднику или завершить. Владелец и менеджер могут
заменить курьера даже в заказе в пути; отключённый сотрудник сразу теряет доступ.

В «Настройки → Шаблоны» владелец может добавить до 50 своих шаблонов с названием,
текстом и подстановками, редактировать их и убирать из списка. Изменения сохраняются
кнопкой «Сохранить шаблоны». Менеджер может просматривать шаблоны своего магазина.
Собственные шаблоны не запускают автоматическую отправку сообщений.

Все телефонные поля начинают с `+996`: местные номера `555123456` и `0555123456`
автоматически сохраняются как `+996555123456`. Другие международные номера с `+`
сохраняют свой код страны. Пустое необязательное поле с одним `+996` не считается
заполненным телефоном; неполные номера по-прежнему отклоняются.

Для разработки frontend нужен Node.js 20.19+ (проверено также в образе Node 22).
Для API достаточно Docker. Для тестов нужны uv и Python 3.13:

```bash
cd backend
uv sync --frozen
```

Можно запускать Django на компьютере: остановить контейнер API и выполнить
`uv run python manage.py runserver 127.0.0.1:8000` из `backend/`.
В этом случае файлы лежат в корневой `media/`, а контейнер использует свой том;
не смешивайте эти хранилища без переноса фотографий.

Настройки магазина, окон, правил напоминаний и шаблонов защищены от перезаписи
из старой вкладки. При конфликте черновик остаётся в форме; кнопка загрузки
актуальных настроек явно заменяет его. Клиенты API передают `version` из GET
в PUT; устаревшая версия возвращает 409, отсутствующая — 400.

Удаление окна не меняет время и цену уже принятого заказа. Его можно редактировать
до готовности; перенос на другую дату/время проверяется по текущим окнам.

После простоя сервера очередь восстанавливает последний пропущенный интервал
для ещё актуального повода, без дублей и автоматической отправки. Восстановленные
записи помечены и используют нейтральный текст без устаревшего срока. Прошедшие
поводы и дни намеренно выключенных напоминаний не восстанавливаются.

Для переноса телефонной книги экспортируйте контакты в файл VCF, затем откройте
«Клиенты → Импорт» и выберите файл — проверка запустится автоматически. В предпросмотре
найдите и отметьте нужные контакты, затем нажмите «Импортировать выбранные».
В этом же окне есть раскрываемая инструкция экспорта для iPhone и Android.
Один контакт сохраняется одной карточкой: имя и фамилия вместе, первый непустой
телефон основной, остальные разные номера — дополнительные. Пустые поля телефонов
пропускаются, одинаковые номера после нормализации объединяются. До 10 разных
номеров на клиента; поиск работает по каждому, в заказе можно выбрать нужный.
В карточке можно добавить/удалить номер и сделать дополнительный основным.
CSV/XLSX экспорт сохраняет дополнительные телефоны в `additional_phones` через `;`;
импорт читает этот необязательный столбец. Основной столбец `phone` сохраняется.
Контакты без корректного имени/телефона и дубли по любому номеру не импортируются;
существующие карточки автоматически не объединяются. До 1000 номеров и 2 МБ за импорт.
Поддержаны vCard 2.1/3.0/4.0; фотографии из телефонной книги не переносятся.

При создании или редактировании клиента «Категория клиента» выбирается из списка:
«Обычный», «VIP», «Корпоративный», «VIP и корпоративный». Дополнительные метки
сохраняются отдельно; смена категории не удаляет их.
Фильтр «VIP и корпоративные» показывает клиентов с обеими метками одновременно;
они также остаются в отдельных фильтрах VIP и корпоративных. «Давно не заказывали» —
90 дней и больше от даты получения в последнем неотменённом заказе, по часовому
поясу магазина. Клиенты без заказов не входят; этот срок независим от настроек
напоминаний о неактивности.

## Основные сценарии

### Демонстрационные данные

При работающем PostgreSQL из `backend/` можно выполнить
`.venv/bin/python manage.py seed_demo --owner owner`. Если у владельца несколько
магазинов, дополнительно укажите `--business UUID` нужного магазина.

Команда добавляет 62 заказа с разными статусами и датами, 24 клиента с получателями
и важными датами, 14 позиций прайса, 6 сотрудников, напоминания, учебные оплаты,
возвраты, отзывы и задачи. Записи помечены как демо; телефоны клиентов вымышленные.
Существующие записи и настройки магазина сохраняются, при ошибке вся операция
откатывается. Повторный запуск не перезаписывает демозаписи и не дублирует заказы.
Даты ранее созданных заказов автоматически не сдвигаются.

Демосотрудники доступны для назначения, но пока не имеют паролей для входа.
Владелец может задать пароль в карточке сотрудника в настройках. Сообщения наружу
не отправляются, деньги не списываются; отметки сообщений и оплат демонстрационные.

### Работа с CRM

- При возвращении во вкладку или браузер на телефоне CRM обновляет данные
  текущего экрана в фоне. Возврат фокуса, восстановление страницы из истории
  браузера и восстановление сети тоже запускают обновление. Открытые карточки
  остаются на экране; формы редактирования сохраняют несохранённый ввод.
- Прайс: фотография при создании/редактировании позиции (JPEG/PNG/WebP до 10 МБ),
  миниатюра слева от названия и просмотр крупнее по нажатию. Карандаш справа от
  крестика открывает изменение названия, цены и фото; крестик архивирует позицию.
  Фото также видно в форме заказа, карточке и задании флориста. Это текущий образец
  из прайса, отдельный от фотографий конкретного заказа. Файлы хранятся локально
  в приватном Docker-томе и входят в резервное копирование. Заменённые/убранные
  файлы подбирает `cleanup_orphan_photos --apply` после 24 часов; действующие
  фотографии, в том числе архивных позиций, защищены от этой очистки.
- Заказы: список, доска, группировка по датам, поиск/фильтры, редактирование,
  назначения, история, отмена с причиной, печатный талон, приватные фото.
  В форме выберите клиента из результатов поиска либо создайте сразу в заказе,
  затем нажмите «Добавить в заказ» для нужных позиций прайса.
- Флорист видит свои задания и свободные новые заказы. Курьер — назначенные ему
  доставки, телефон получателя, адрес и возможность сообщить о проблеме.
- Оплаты и возвраты — записи вручную, без списания денег с банковской карты.
  Суммы считает сервер; повтор операции с тем же ключом не дублирует оплату.
- Клиенты: заметки, согласие на сообщения, получатели, важные даты, история,
  импорт CSV/XLSX/VCF с предпросмотром и выбором контактов, экспорт CSV/XLSX. Заголовки таблиц:
  `name,phone,notes` или `Имя,Телефон,Заметка`. Максимум 1000 строк / 2 МБ.
  Дубли телефона пропускаются; импорт не выдаёт согласие на сообщения.
- Напоминания: важные даты и период без заказов, отдельные шаблоны, тихие часы,
  пауза при жалобе, перенос на завтра и пропуск события в текущем году.
  WhatsApp открывает подготовленный текст; сотрудник отправляет его сам и отдельно
  отмечает отправку/ответ/заказ. Celery обновляет очередь каждые 15 минут.
- Публичная ссылка показывает статус и окно получения, позволяет оставить отзыв
  после вручения. Статус проверяется автоматически раз в 15 секунд без перезагрузки
  страницы. В скрытой вкладке и без сети проверки приостанавливаются; при возврате
  на страницу или восстановлении сети статус запрашивается сразу. После вручения
  или отмены автоматические проверки прекращаются. При временном сбое повторная
  проверка идёт через 30 секунд; кнопка ручного обновления остаётся доступной.
  Перевыпуск ссылки отменяет прежнюю. Имена, адреса, цены, фото
  и внутренние заметки по этой ссылке не доступны.

## Папки чатов

В WhatsApp слева от списка диалогов есть отдельная колонка папок. Владелец и
менеджер могут создать до 30 папок с собственными названиями (до 40 символов),
переименовать и удалить их через «Настроить». Папки общие для команды компании,
как и текущая переписка; другие компании их не видят.

Добавляйте чат в одну или несколько папок через правый клик → «Добавить в папки»
или кнопку под шапкой переписки. Наведение на пункт меню открывает боковой список:
отметки сохраняются сразу, можно выбрать несколько папок. Подменю также открывается
кликом или стрелкой вправо; Escape/стрелка влево возвращает в меню чата.
В окне выбора под шапкой можно создать новую папку.
Папки и состав сохраняются на сервере, выбранная папка — в этом браузере отдельно
для пользователя и компании. Фильтры, поиск и пагинация работают внутри папки;
счётчик в колонке показывает открытые диалоги, закрытые доступны через «Архив».
Удаление папки требует подтверждения и сохраняет переписки во «Все чаты» и
других папках. При удалении выбранной папки открывается общий список.

Для обновления backend нужна миграция `messaging.0003_chat_folders` и пересборка
локальных API, worker и beat по инструкции запуска выше.

## Уведомления чатов

Кнопка динамика в верхней панели включает звук и проигрывает короткий пробный
сигнал. Выбор сохраняется в этом браузере для пользователя. После перезапуска
браузера нужен первый клик или нажатие клавиши, чтобы браузер разрешил звук.
Несколько открытых вкладок CRM не должны одновременно озвучивать одно сообщение.

Новое входящее вызывает уведомление в CRM и мигание заголовка вкладки со
счётчиком непрочитанных. При возвращении в окно или клике в CRM мигание прекращается,
счётчик сохраняется до прочтения. Старые сообщения при загрузке не озвучиваются.
Проверка входящих выполняется раз в 10 секунд, в том числе в фоне; браузер может
приостанавливать таймеры неактивных вкладок. Системные push-уведомления не используются.
Проверки логики и звукового сигнала: `cd frontend && npm run test:notifications`.

## Автозаполнение черновика

В чатах добавлен разбор переписки для активного черновика: фоновые предложения,
кнопка «Обновить из чата», защита ручных правок и проверка перед созданием заказа.
Ministral подключается через серверный ключ и модель в `TAPME_AI_MODEL`.
С 27 октября локальный тест использует Ministral 3 8B (`ministral-8b-2512`)
только для разрешённого вымышленного чата. Без ключа локально доступен
явно обозначенный demo для тестового WhatsApp.
[Настройка и ограничения](docs/runbooks/chat-draft-autofill.md).

## Проверки

Из `backend/` при работающем PostgreSQL:

```bash
uv run pytest -q
uv run python -m pytest -p no:django -p no:cacheprovider -c /dev/null tests/unit -q
uv run mypy
uv run ruff check .
uv run ruff format --check .
uv run python manage.py makemigrations --check --dry-run
uv run python manage.py spectacular --validate --fail-on-warn --file /tmp/tapme-openapi.yaml
```

Интеграционные тесты работают в отдельной базе `test_tapme_flowers`; unit-тесты
не используют Django и БД. Есть проверки конкурентных оплат и взятия заказа,
изоляции бизнесов, ролей, CSRF, токенов, напоминаний, импорта и восстановления фото.

Из `frontend/`, когда API запущен в Docker и доступен `backend/.venv/bin/python`:

```bash
npm run build
npm run format:check
npx playwright install chromium firefox
npm run test:e2e
```

Три сценария выполняются в обоих браузерах. Каждый создаёт отдельный бизнес
`E2E`, проходит настоящий API и удаляет только свои записи и фотографии.
Playwright запускает Vite автоматически; снимки экранов — `/tmp/tapme-*.png`.

## Данные и эксплуатация

Порты разработки доступны на localhost: PostgreSQL 55432, API 8000, Redis 6379,
frontend 5173. В контейнерной сети используются `postgres:5432`, `redis:6379`.
Именованные тома сохраняют БД, фото, Redis и расписание Celery.

```bash
docker compose --profile app --profile jobs ps
docker compose --profile jobs logs --tail=100 worker beat
python3 scripts/backup.py
```

`down -v` удаляет тома — не используйте её для обычной остановки.
