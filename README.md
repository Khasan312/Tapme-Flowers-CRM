# Tapme Flowers

CRM для цветочных магазинов: Django REST Framework + PostgreSQL, React/TypeScript,
Celery + Redis. Исходный дизайн `tapme-flowers-v1.html` сохранён.

Интерфейс перенесён по структуре макета: общий поиск, пять вкладок настроек,
плитки и задачи заказов, страницы клиентов, напоминания и доставка по окнам.
[Сверка и снимки](docs/design-audit/README.md).
Сначала прочитайте [SESSION_HANDOFF.md](SESSION_HANDOFF.md), если продолжаете работу.

Реализованы заказы от приёма до вручения, рабочие экраны флориста и курьера,
ручной учёт оплат и возвратов, приватные фото, клиенты и получатели, прайс,
напоминания, отзывы/жалобы, настройки магазина и сотрудники. Все экраны работают
с API. Бизнес-правила и сценарии используют Python-контракты вместо Django ORM.

## Запуск существующего окружения

На текущем компьютере `.env` уже настроен. Логин **owner**, локальный пароль —
значение `TAPME_BOOTSTRAP_PASSWORD` в `.env`. Это владелец своего бизнеса,
не глобальный администратор Django. Если пароль изменён в интерфейсе, используйте
новый: bootstrap-переменная не меняет пароль существующей учётной записи.

```bash
docker compose --profile app build api
docker compose --profile app run --rm api python manage.py migrate
docker compose --profile app --profile jobs up -d --wait
cd frontend
npm ci
npm run dev
```

Открыть в Firefox: [http://127.0.0.1:5173](http://127.0.0.1:5173).
API: [проверка готовности](http://127.0.0.1:8000/health/),
[Swagger после входа](http://127.0.0.1:8000/api/docs/).
При изменении backend повторите сборку и `up` обоих профилей, чтобы обновились
API, worker и beat. Vite автоматически подхватывает изменения frontend.

Для первого запуска на другом компьютере создайте `.env` из `.env.example`,
задайте собственные `POSTGRES_PASSWORD`, `DJANGO_SECRET_KEY` и
`TAPME_BOOTSTRAP_PASSWORD`, выполните сборку/миграции, затем:

```bash
docker compose --profile app run --rm api python manage.py bootstrap_business --name 'Tapme Flowers' --username owner
```

Команда не перезаписывает существующий пароль. Создание второго независимого
магазина выполняется той же командой с другим названием и логином владельца.
Сотрудники создаются владельцем в «Настройках»; там же роли, блокировка доступа,
сброс пароля, контакты магазина и окна доставки. Шаблоны находятся в «Напоминаниях».

Для разработки frontend нужен Node.js 20.19+ (проверено также в образе Node 22).
Для API достаточно Docker. Для тестов нужны uv и Python 3.13:

```bash
cd backend
uv sync --frozen
```

Можно запускать Django на компьютере: остановить контейнер API и выполнить
`uv run python manage.py runserver 127.0.0.1:8000` из `backend/`.
В этом случае файлы лежат в корневой `media/`, а контейнер использует свой том;
не смешивайте эти хранилища без переноса фотографий.

## Основные сценарии

- Заказы: список, доска, группировка по датам, поиск/фильтры, редактирование,
  назначения, история, отмена с причиной, печатный талон, приватные фото.
  В форме выберите клиента из результатов поиска либо создайте сразу в заказе,
  затем нажмите «Добавить в заказ» для нужных позиций прайса.
- Флорист видит свои задания и свободные новые заказы. Курьер — назначенные ему
  доставки, телефон получателя, адрес и возможность сообщить о проблеме.
- Оплаты и возвраты — записи вручную, без списания денег с банковской карты.
  Суммы считает сервер; повтор операции с тем же ключом не дублирует оплату.
- Клиенты: заметки, согласие на сообщения, получатели, важные даты, история,
  импорт CSV/XLSX с предпросмотром и экспорт. Заголовки импорта:
  `name,phone,notes` или `Имя,Телефон,Заметка`. Максимум 1000 строк / 2 МБ.
  Дубли телефона пропускаются; импорт не выдаёт согласие на сообщения.
- Напоминания: важные даты и период без заказов, отдельные шаблоны, тихие часы,
  пауза при жалобе, перенос на завтра и пропуск события в текущем году.
  WhatsApp открывает подготовленный текст; сотрудник отправляет его сам и отдельно
  отмечает отправку/ответ/заказ. Celery обновляет очередь каждые 15 минут.
- Публичная ссылка показывает статус и окно получения, позволяет оставить отзыв
  после вручения. Перевыпуск ссылки отменяет прежнюю. Имена, адреса, цены, фото
  и внутренние заметки по этой ссылке не доступны.

## Проверки

Из `backend/` при работающем PostgreSQL:

```bash
uv run pytest -q
uv run python -m pytest -p no:django -p no:cacheprovider -c /dev/null tests/unit -q
uv run mypy
uv run ruff check .
uv run ruff format --check .
uv run python manage.py makemigrations --check --dry-run
uv run python manage.py spectacular --validate --fail-on-warn --file /tmp/tapme-openapi.yaml
```

Интеграционные тесты работают в отдельной базе `test_tapme_flowers`; unit-тесты
не используют Django и БД. Есть проверки конкурентных оплат и взятия заказа,
изоляции бизнесов, ролей, CSRF, токенов, напоминаний, импорта и восстановления фото.

Из `frontend/`, когда API запущен в Docker и доступен `backend/.venv/bin/python`:

```bash
npm run build
npm run format:check
npx playwright install chromium firefox
npm run test:e2e
```

Три сценария выполняются в обоих браузерах. Каждый создаёт отдельный бизнес
`E2E`, проходит настоящий API и удаляет только свои записи и фотографии.
Playwright запускает Vite автоматически; снимки экранов — `/tmp/tapme-*.png`.

## Данные и эксплуатация

Порты разработки доступны на localhost: PostgreSQL 55432, API 8000, Redis 6379,
frontend 5173. В контейнерной сети используются `postgres:5432`, `redis:6379`.
Именованные тома сохраняют БД, фото, Redis и расписание Celery.

```bash
docker compose --profile app --profile jobs ps
docker compose --profile jobs logs --tail=100 worker beat
python3 scripts/backup.py
python3 scripts/verify_backup.py backups/ИМЯ_СОЗДАННОЙ_КОПИИ
docker compose --profile app --profile jobs stop
```

Последняя команда останавливает только этот проект и сохраняет данные.
`down -v` удаляет тома — не используйте её для обычной остановки.

Для рабочего сервера подготовлены отдельный Compose, Gunicorn, Caddy/HTTPS,
закрытое локальное или S3-хранилище, резервирование и команды восстановления.
См. [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Сервер, домен и облачный провайдер
пока не подключены; плановый внешний мониторинг и копии вне сервера нужно настроить
на выбранной площадке до пилота.
