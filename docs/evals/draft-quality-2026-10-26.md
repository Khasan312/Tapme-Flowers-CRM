# Проверка автозаполнения — 26 октября 2026

На одинаковом наборе из 40 **вымышленных** диалогов сравнили `ministral-3b-2512`
и `ministral-8b-2512`: один запуск каждой модели на каждый диалог, temperature 0.
28 примеров использованы при разработке правил, 12 заранее отложены для контроля.
После получения результатов контрольных примеров правила и prompt не подгонялись.

Это результат всей цепочки **модель → проверка цитат → правила дат → проверка полей**,
а не оценка модели без серверной обработки. В наборе короткие, преимущественно
русские сообщения, часто с явными подписями полей; это проще реальных переписок.

У 3B два результата отклонены валидатором (`invalid_result`), у 8B один запрос
завершился ошибкой `provider_unavailable` после 15 секунд. Пустой, ошибочный или
неполный результат считается провалом, а не исключается из оценки.

*У запроса с таймаутом расход неизвестен. Цена рассчитана по возвращённым токенам
и [стандартным тарифам Mistral](https://docs.mistral.ai/inference/pricing):
3B — $0,10 / миллион входных и выходных токенов, 8B — $0,15 для обоих направлений.
Это оценка, не выписка списаний; не учтены кеширование, налоги и неизвестный расход
ошибочного запроса. При такой же длине контекста получается примерно $0,11 / $0,16
за 1000 разборов. Длинная история переписки увеличит цену.

Замер выполнялся с двумя параллельными запросами. Не является нагрузочным тестом.
Один прогон на малом наборе не даёт гарантии стабильности процентов.

## Что показала проверка

- 3B часто пропускает способ получения даже при явных «доставка»/«самовывоз»;
  пропуски были и в текстах открытки. При проверке бюджета были отклонённые ответы.
- 8B извлекла больше нужных данных, но однажды записала пожелание об упаковке в
  `address_details`, пропустив `notes`. Дословная цитата доказывает наличие текста,
  но сама по себе не доказывает правильность выбора поля.
- Даты и интервалы из явных фраз вычисляет Python по времени сообщения и часовому
  поясу магазина. Пустые/неоговорённые окна из справочника не выбираются.
- Все предложения остаются непроверенными до подтверждения менеджера. Ручные
  значения заблокированы от автоматической перезаписи, включая окно получения.
- «К 15:00» сохраняется в пожелании по времени, не превращает заказ в самостоятельный
  новый режим точной доставки. Для конвертации менеджер по-прежнему выбирает окно.

Для следующего пилота предпочтительнее **8B**, однако локальная настройка пока
оставлена **3B**: `TAPME_AI_TEST_CHAT_ID` разрешает внешний разбор только ранее
созданного вымышленного чата. Доступ к реальным клиентским перепискам не расширен.

S-04 (репрезентативные обезличенные диалоги магазина) и Q-13 остаются открытыми.
Нужны новые примеры с разговорным языком, опечатками, кыргызским языком, неоднозначными
датами, изменениями нескольких позиций и историей ручных правок. Неподдержанные
фразы, вопросы и неоднозначные случаи могут оставаться для ручного заполнения.
Старые поля черновика, не предложенные при повторном разборе, автоматически не стираются.
