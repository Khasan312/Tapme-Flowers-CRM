# Автозаполнение черновика из переписки

Реализовано 26.10.2026. ИИ предлагает поля активного черновика, менеджер проверяет
их и отдельно создаёт заказ. Отправки сообщений и подтверждения оплаты здесь нет.

## Текущий локальный тест с настоящей моделью — 27 октября

По запросу пользователя локальная `.env` переключена на `ministral-8b-2512`.
API, worker и beat пересозданы; модель подтверждена реальным запросом через
механизм автозаполнения (`applied`, без ошибки). Внешняя обработка ограничена одним заранее созданным
вымышленным чатом «Тест автозаполнения»:

```dotenv
TAPME_AI_ENABLED=true
TAPME_AI_MODE=mistral
TAPME_AI_MODEL=ministral-8b-2512
TAPME_AI_TEST_CHAT_ID=95c82f11-8649-4655-9eef-b6d07cb1950a
```

При непустом `TAPME_AI_TEST_CHAT_ID` сервер разрешает модель только этому диалогу,
только при DEBUG и fake Meta/канале. Остальные чаты, live-канал и production
заблокированы как для ручного запуска, так и для worker. Реальные переписки
пока не допущены: S-04 и Q-13 остаются открытыми. Ключ не хранится в Git.

### Проверка качества и источников

Модель возвращает типизированные значения с дословными цитатами (`message_id`,
`quote`). Сервер проверяет присутствие цитат в переписке, значения и каталог;
сохраняет evidence в metadata поля. Заполненные вручную и подтверждённые поля защищены.
При явном нажатии «Обновить из чата» очищенные поля можно заполнить повторно;
фоновое обновление продолжает уважать даже ручную очистку. Частично введённые
телефон и интервал не заменяются. Повторно заполненные поля требуют проверки.
Телефон с одним `+`, пробелами/скобками или только кодом `+996` считается пустым;
сохранение приводит его к пустой строке. Это правило работает и для ранее
сохранённых черновиков при явном обновлении. Введённые цифры номера защищены.
Даты, интервалы и пожелания по времени вычисляет Python из явных фраз по времени
сообщения и часовому поясу магазина; модель не выбирает окно из справочника.
Неподдержанные формулировки остаются для ручного заполнения. Цитата сама по себе
не гарантирует правильный выбор поля — проверка менеджера обязательна.

Сравнение на 40 вымышленных диалогах (28 development, 12 отложенных):
3B — 66/86 ожидаемых полей, 24/40 диалогов целиком;
8B — 78/86 полей, 32/40 диалогов. У 8B одно лишнее поле и один таймаут,
у 3B два отклонённых ответа и больше пропусков. Это результат всей цепочки
с серверными правилами, не оценка модели в отрыве от них.

Подробности и ограничения: [отчёт](../evals/draft-quality-2026-10-26.md).
S-04/Q-13 остаются открытыми. С 27 октября текущая локальная модель — 8B;
допуск к реальным клиентским перепискам не расширен.

Для явного повторного запуска (реальные запросы, могут расходовать платную квоту):

```bash
backend/.venv/bin/python scripts/check_mistral_drafts.py --live
# Только 3B, только примеры разработки:
backend/.venv/bin/python scripts/check_mistral_drafts.py --live --models ministral-3b-2512 --split development
```

Скрипт использует только файл `backend/tests/evals/draft_synthetic_v1.json`, не читает
БД; отчёт по умолчанию `/tmp/tapme-mistral-quality-v1.json`. Без `--live` запросов нет.
Старые неподтверждённые AI-поля не удаляются только из-за отсутствия их в новом
ответе: проверяйте прежний черновик или отложите его и создайте новый в тестовом чате.

## Локальная проверка без ключа

В локальном `.env`:

```dotenv
TAPME_AI_ENABLED=true
TAPME_AI_MODE=demo
TAPME_AI_MODEL=ministral-3b-2512
```

`demo` работает только при `DJANGO_DEBUG=true`, `TAPME_META_MODE=fake` и для
канала `provider_mode=fake`. Это разбор нескольких предсказуемых шаблонов, **не ИИ**.
Интерфейс прямо обозначает демонстрационный режим. Данные не покидают процесс.

1. В «Чатах» откройте тестовый диалог и создайте черновик. Если точек несколько,
   выберите точку и сохраните черновик.
2. В «Настройки → Каналы → Симулятор входящего сообщения» отправьте в этот диалог
   пример (замените название букета на точное название из вашего прайса):

   ```text
   Нежный букет; завтра; доставка; 10:00–12:00;
   Адрес: Бишкек, Чуй 120
   Получатель: Айдана
   Телефон получателя: +996700123456
   Открытка: С праздником!
   ```

3. После нового сообщения активный черновик обновится в фоне. Пауза для объединения
   сообщений — 4 секунды, планировщик и опрос интерфейса — каждые 5 секунд.
   Обработка самого входящего симулятора может добавить до 10 секунд.
4. «Обновить из чата» запускает повторный разбор. Несохранённые правки сначала
   сохраняются; пустые поля заполняются заново, заполненные вручную сохраняются.
   Если в сообщениях нет подходящих данных, поле остаётся пустым. Ошибка разбора
   не снимает защиту полей; правки, внесённые во время запроса, не перезаписываются.
5. Проверьте поля, отмеченные «уточнить». Исправление отдельного поля подтверждает
   его; «Проверил заполнение» подтверждает все оставшиеся. Сохраните черновик.
   До проверки сервер запрещает превращать его в заказ.

Ограничения demo: точное название одной позиции с количеством 1; «сегодня»,
«завтра», «послезавтра» или ISO-дата; существующий интервал; отдельные строки
«Адрес:», «Получатель:», «Телефон получателя:», «Открытка:», «Пожелания:».
«К 18:00» сохраняется как пожелание, окно автоматически не выдумывается.
Произвольные фразы и сложные исправления требуют настоящей модели.

## Подключение Ministral

1. Получить ключ в [Mistral Studio](https://console.mistral.ai/), хранить только на
   сервере в `.env`, не отправлять его в переписку и не добавлять в Git.
2. До работы с реальными переписками выполнить S-04 (30–50 обезличенных диалогов,
   качество не ниже 85% по целевым полям) и Q-13 (условия обработки данных).
   Локальные тесты с подставными ответами не доказывают качество модели.
3. Настроить:

   ```dotenv
   TAPME_AI_ENABLED=true
   TAPME_AI_MODE=mistral
   TAPME_AI_MODEL=ministral-8b-2512
   MISTRAL_API_KEY=<вставить ключ локально>
   ```

4. Пересоздать `api`, `worker`, `beat`, чтобы они получили переменные окружения.
   Проверить разбор обезличенного примера, задержку, расход токенов и ошибки.
   Без ключа этот режим недоступен; скрытой подмены на demo нет.
5. `TAPME_AI_ENABLED=false` отключает все обращения к модели и оставляет ручной ввод.

Официальный SDK `mistralai` 2.x используется только в инфраструктурном адаптере.
Приложение зависит от `ChatExtractor`. Контракт проверен через `httpx.MockTransport`,
включая JSON Schema, неполные ответы, таймаут и один повтор при 429/5xx.
Таймаут одной попытки — 15 секунд. Логи содержат только статус, режим и длительность;
состояние черновика содержит счётчики токенов, без копии запроса или ответа.

## Защита данных и конфликтов

- Контекст: не более 40 сообщений за 7 дней, после предыдущего завершённого
  черновика этого разговора; без автоматических и системных сообщений. Часы
  сообщения передаются в часовом поясе компании. Лимит текста — 80 000 символов.
- Передаются текущий черновик, окна выбранной точки и первые 500 активных позиций
  прайса (стабильная сортировка по названию/ID). Более крупный каталог требует
  отдельного поиска кандидатов. Другие клиенты, сотрудники и история их заказов
  не передаются. Фото, PDF и аудио пока не разбираются.
- Проверяются права инициатора, магазин, активность точки, товарные ID, поля,
  источник сообщения, формат даты/окна и цены из прайса. Неизвестное поле или
  неверный результат отклоняет весь ответ.
- Результат применяется только к активному черновику той же версии, тому же
  клиенту/точке/инициатору и последнему сообщению. Изменение окон, прав или
  доступности товара также отменяет устаревший результат.
- Все применённые предложения требуют проверки менеджера. Ручные и подтверждённые
  поля блокируются. Если форма содержит несохранённый ввод, она не заменяется
  результатом фонового обновления: показывается конфликт, текст остаётся на экране.
- Запросы выполняются вне транзакции. Состояние `running` не дублируется другим
  worker; после прерывания запрос не повторяется сам (мог быть оплачен), доступен
  ручной повтор. Ошибка модели сохраняет ручной черновик.
- Черновики, созданные до миграции, включают фоновые обновления после первого
  нажатия «Обновить из чата». Новые — после создания менеджером. Новый разговор
  сам по себе не создаёт черновик.
