# Подключение номера для заказов WhatsApp (ручной режим, пилот)

Для встречи в понедельник, 19 октября 2026. Требования к коду — в
[docs/spec/12-chats-monday.md](../spec/12-chats-monday.md) (решения D-25…D-29).

**Важно.** Подключаем **только новый номер для заказов**. Основной номер магазина не
трогаем: не регистрируем, не удаляем, не переносим.

Названия пунктов в интерфейсе Meta периодически меняются. Шаги составлены по
документации WhatsApp Cloud API; если пункт называется иначе — ищите по смыслу.
Живой интерфейс Meta при составлении не проверялся.

## Кто что делает

- **Владелец магазина** входит в свой Facebook и бизнес-аккаунт Meta, принимает код из SMS,
  вводит PIN. Секреты видит и вставляет только он (или делает это при нас на своём экране).
- **Tapme** ведёт по шагам, вставляет данные в Tapme вместе с владельцем, проверяет связь.
- Токен и App Secret **не пересылаются** в мессенджерах и почте — только вставляются
  в форму Tapme.

## Подготовка (до понедельника)

| Что | Кто | Проверка |
| --- | --- | --- |
| Новая SIM на магазин в телефоне, номер принимает SMS или звонок, на нём **нет** WhatsApp | магазин | Попробовать позвонить на номер |
| Аккаунт Facebook владельца с двухфакторной защитой | магазин | Вход на facebook.com |
| Бизнес-аккаунт магазина на business.facebook.com (создать, если нет: название магазина, имя владельца, рабочая почта) | магазин | Владелец — администратор |
| Придумать 6-значный PIN двухэтапной проверки номера и сохранить его у владельца | магазин | Записан в надёжном месте |
| Сервер Tapme с доменом и HTTPS, страницы `https://<домен>/privacy` и `/terms` открываются | Tapme | Открыть в браузере с телефона |
| На сервере версия с чатами, проверка раздела 8 из ТЗ пройдена в режиме `fake`; включён `TAPME_META_MODE=live` | Tapme | Отчёт проверки |
| Резервная копия базы перед включением | Tapme | `scripts/backup.py` |

## Шаги в понедельник

### A. Приложение Meta (developers.facebook.com, вход под Facebook владельца)

1. «Мои приложения» → «Создать приложение». Вариант использования — подключение к
   клиентам через WhatsApp (тип Business). Название: «Tapme <магазин>». Привязать к
   **бизнес-аккаунту магазина**.
2. В приложении добавить продукт **WhatsApp** и выбрать бизнес-аккаунт магазина (аккаунт
   WhatsApp Business создастся или выберите существующий).

### B. Номер для заказов

3. WhatsApp → «Настройка API» → «Добавить номер телефона»: имя для клиентов (например
   «Tapme Flowers · заказы» — имя должно быть связано с магазином), категория, номер
   для заказов → код по SMS или звонку → подтвердить.
4. На той же странице скопировать **Phone number ID** и **WhatsApp Business Account ID**.

### C. Постоянный токен

5. business.facebook.com → «Настройки компании» → «Пользователи» → «Системные пользователи»
   → «Добавить», роль «Администратор».
6. «Назначить ресурсы»: приложение «Tapme <магазин>» — полный доступ; аккаунт WhatsApp
   Business — полный доступ.
7. «Создать токен»: приложение «Tapme <магазин>», срок действия «Никогда», разрешения
   `whatsapp_business_messaging` и `whatsapp_business_management`. Токен показывается
   один раз — сразу вставить в Tapme (шаг 11).

### D. Секрет и рабочий режим приложения

8. Приложение → «Настройки» → «Основное»: скопировать **App Secret** (нужен пароль
   Facebook); указать «URL политики конфиденциальности» `https://<домен>/privacy` и
   «URL условий» `https://<домен>/terms`; сохранить.
9. Переключить приложение в **рабочий режим** (Live). Если Meta не даёт переключить или
   требует проверку — см. «План Б».

### E. Tapme: подключение

10. Войти в Tapme владельцем → Настройки → **Каналы** → WhatsApp.
11. Вставить Phone number ID, WhatsApp Business Account ID, токен, App Secret →
    «Сохранить и проверить» → отметка «Токен работает · номер +996… · «имя»».
12. «Зарегистрировать номер (PIN)» → ввести PIN из подготовки → отметка «Номер
    зарегистрирован в Cloud API». Ответ «уже зарегистрирован» — тоже нормально.

### F. Вебхук

13. Meta → WhatsApp → «Конфигурация» → «Вебхук» → «Изменить»: вставить **Callback URL** и
    **Verify token** из Tapme → «Проверить и сохранить». В Tapme появится «Вебхук
    подтверждён».
14. Там же «Поля вебхука» → подписаться на `messages` (обязательно),
    `message_template_status_update`, `phone_number_quality_update`, `account_update`.
15. В Tapme нажать «Подписать» → отметка «Приложение подписано на сообщения этого аккаунта».

### G. Проверка

16. С личного телефона написать «Привет» на номер для заказов → в Tapme «Чаты» за
    несколько секунд появился разговор с меткой «новый клиент», клиенту пришёл автоответ.
17. Ответить из Tapme текстом и фото → пришло на телефон, в Tapme видны галочки
    «доставлено» и «прочитано».
18. Второй сотрудник с открытой CRM слышит звук и видит счётчик «Чаты».
19. «Отправить QR» → картинка QR и текст пришли.
20. Отметка «Тестовое сообщение получено» в Каналах — подключение завершено.

### H. После подключения

21. На **основном** номере в приложении WhatsApp Business: Инструменты →
    «Приветственное сообщение» → вставить текст со ссылкой (Tapme → Каналы → Главный номер
    → «Скопировать»).
22. Ссылку `wa.me/<номер для заказов>` добавить в описание Instagram и на сайт.
23. В WhatsApp Manager добавить способ оплаты (нужен позже для шаблонов) и подать шаблоны
    сообщений по статусам (T-13).
24. Начать проверку бизнеса магазина в Meta («Настройки компании» → центр безопасности),
    если Meta её предлагает — она повышает лимиты сообщений по инициативе магазина.
25. Записать в `SESSION_HANDOFF.md`: что подключено, время, кто проверял, что не прошло.

## Если что-то не работает

| Признак | Вероятная причина | Что сделать |
| --- | --- | --- |
| «Проверить и сохранить» вебхука в Meta не проходит | Неверный Verify token или адрес; сервер недоступен извне; нет HTTPS | Скопировать заново из Tapme; проверить `curl "https://<домен>/api/v1/webhooks/meta/whatsapp/<key>/?hub.mode=subscribe&hub.verify_token=<token>&hub.challenge=123"` — должно вернуть `123` |
| Сообщения клиента не появляются в Tapme | Не подписано поле `messages`; приложение не подписано на аккаунт (шаг 15); приложение в режиме разработки; неверный App Secret (в логах — отказ подписи) | Проверить шаги 9, 14, 15; заменить App Secret в Tapme |
| «Токен работает» не появляется (ошибка доступа, код 190) | Токен скопирован не полностью, у системного пользователя нет ресурсов или разрешений | Шаги 6–7 заново, новый токен |
| Ошибка «номер уже используется в WhatsApp» | На номере есть приложение WhatsApp | Это должен быть **новый** номер для заказов. Только для него: удалить аккаунт WhatsApp в приложении на этом номере, подождать несколько минут, повторить. Основной номер не трогать |
| Отправка: «получатель не в списке разрешённых» | Используется тестовый номер Meta или приложение не в рабочем режиме | Шаг 9; отправлять со своего номера для заказов |
| Отправка: «вне окна 24 часов» | Клиент молчит больше 24 часов | Ожидаемо в пилоте; нужен шаблон (следующий этап) |
| У клиентов вместо имени номер | Имя на проверке Meta | Можно работать; имя появится после одобрения |
| Код из SMS не приходит | Номер не принимает SMS | Выбрать подтверждение звонком |

## План Б (если Meta не пускает в рабочий режим)

1. Сегодня — показать магазину весь путь на **тестовом номере Meta** (в режиме разработки
   Meta разрешает писать на несколько добавленных номеров получателей): Tapme работает
   так же, меняются только ID и токен.
2. Подать проверку бизнеса магазина и/или приложения, которую требует Meta.
3. Параллельно принять решение Q-01 (подключение через посредника), чтобы не ждать.
4. Записать, что именно потребовала Meta, в `docs/spec/11-open-questions-and-risks.md`
   (R-01) и в `SESSION_HANDOFF.md`.
