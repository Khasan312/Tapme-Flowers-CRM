# Подключение магазина через панель TapMe

Панель команды TapMe: `/crm-flowers/platform/` на опубликованном сайте,
`/platform/` при локальном запуске Vite. Она использует тот же backend и базу,
но отдельное право `businesses.manage_platform`. Роли `owner`, `manager`,
`florist`, `courier` и флаг Django `is_staff` сами по себе доступа не дают.
Администратор платформы не становится участником магазинов и не получает
автоматический доступ к их заказам, клиентам и переписке.

## Первый вход команды TapMe

После проверенного релиза и миграций один раз создайте **отдельные личные**
учётные записи администраторов. Не используйте логин существующего владельца.
Команда откажется переиспользовать или повысить права существующей учётной записи.

Локально, из `backend/`:

```bash
uv run python manage.py migrate
uv run python manage.py bootstrap_platform_admin --username tapme.arsen
uv run python manage.py bootstrap_platform_admin --username tapme.khasan
```

На production с текущей схемой blue/green, после публикации версии с этой командой:

```bash
read -r tapme_slot tapme_revision < /srv/tapme/state/current
sudo docker exec -it "tapme-api-${tapme_slot}" python manage.py bootstrap_platform_admin --username tapme.arsen
sudo docker exec -it "tapme-api-${tapme_slot}" python manage.py bootstrap_platform_admin --username tapme.khasan
```

Пароль вводится скрыто в терминале; минимум 12 символов и стандартная проверка
сложности Django. Не передавайте пароль аргументом команды. Для автоматизированного
локального окружения поддерживается `TAPME_PLATFORM_ADMIN_PASSWORD`; не храните его
в Git. Команда выдаёт только право управления платформой, без `is_staff` и
`is_superuser`. Создание пользователей платформы через браузер не предусмотрено.

## Первый магазин: Dion Flowers

1. Войдите в панель под своей учётной записью TapMe.
2. Проверьте список: если Dion Flowers уже создан, используйте его карточку
   «Доступ владельца». Не создавайте вторую компанию только ради нового пароля.
3. Если компании ещё нет, нажмите «Подключить магазин», укажите Dion Flowers,
   имя владельца и его личный логин, например `dion.aigul`.
4. Скопируйте выданный доступ и передайте владельцу лично. Пароль автоматически
   генерируется и показывается в ответе только один раз. Сервер хранит его хеш.
5. Владелец входит в обычную CRM и задаёт свой пароль. До этого сервер блокирует
   рабочие API, включая список компаний и создание сотрудников.
6. После смены пароля: «Настройки → Сотрудники → Пригласить». Владелец создаёт
   личные учётные записи менеджеров, флористов и курьеров, назначает существующие
   роли и доступные точки. Произвольного конструктора ролей в этой версии нет.

Имя пользователя — идентификатор человека. Префикс `dion.` удобен, но не определяет
роль и границы доступа. Изоляция обеспечивается `Membership` и проверками API.
Компания может иметь несколько точек (`Shop`); филиалы не считаются отдельными
компаниями в панели.

## Восстановление доступа

«Доступ владельца → Восстановить доступ → Выдать новый пароль». Старый пароль
сразу теряет силу, старые сессии перестают проходить проверку, новый пароль
обязательно меняется при входе. Сброс возможен только для активного владельца
выбранной компании. Учётные записи администраторов TapMe через этот сценарий
не сбрасываются. Действие записывается в журнал с администратором, компанией,
владельцем и временем; пароль в журнал не попадает. Последние 100 действий
доступны во вкладке «Журнал действий».

## Выпуск и откат

Три добавочные миграции: поле первого входа, право управления платформой и журнал
действий. Для старых пользователей `must_change_password=false`; их доступы
не меняются. SQL-default поля сохранён для совместимости со старыми процессами
при переключении выпуска. Production не получает демоданные или администраторов
автоматически: bootstrap выполняется отдельно после релиза.

Если после выдачи временных доступов нужен откат на версию **без** проверки
`must_change_password`, сначала отключите ещё не активированные учётные записи
владельцев (`is_active=false`) либо завершите смену их паролей. Старая версия
не умеет принудительно отправлять пользователя на смену временного пароля.
