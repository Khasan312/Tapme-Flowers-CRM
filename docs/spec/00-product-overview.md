# 00. Обзор продукта, решения и итоги ревью

## 1. Проблема

Цветочные магазины Бишкека продают в WhatsApp и Instagram. Менеджер вручную
переписывается, переносит заказ из чата в систему, отправляет QR, сверяет оплату и
передаёт заказ флористу. Клиентская база неполная: в CRM попадает только тот, кого
менеджер внёс сам. Партнёр по дизайну (одна марка, несколько точек) прямо требует
CRM, которая сама разбирает переписку WhatsApp и Instagram, как Kelesu, — но боится
потерять основной номер WhatsApp из-за ботов и рассылок.

Если не решить: магазин остаётся в WhatsApp на телефоне, Tapme становится
«ещё одной таблицей», а конкурент с общими входящими забирает рынок.

## 2. Цели релиза

| # | Цель | Как измеряем | Порог успеха пилота |
| --- | --- | --- | --- |
| G1 | Заказы из переписки попадают в CRM без ручного ввода | доля заказов пилотного магазина с `source` = `whatsapp`/`instagram`/`bot` от всех заказов за неделю | ≥ 50 % к концу 2-й недели после запуска |
| G2 | Клиент получает ответ быстро | медиана времени от входящего сообщения до первого ответа человека или бота в рабочие часы | ≤ 5 мин; бот — ≤ 10 с |
| G3 | Клиентская база пополняется сама | доля новых клиентов, созданных из чатов, от всех новых клиентов | ≥ 80 % |
| G4 | Основной номер магазина в безопасности | число блокировок или ограничений номеров магазина; оценка качества номера заказов у Meta | 0 блокировок; качество «высокое» |
| G5 | Напоминания приносят заказы | конверсия «написали → заказали» по напоминаниям за месяц | ≥ 10 % |

## 3. Не-цели релиза

| Не делаем | Почему |
| --- | --- |
| Подключение основного номера WhatsApp (coexistence) | Решение партнёра: максимальная защита основного номера (D-01). Возможен позже в режиме «только чтение» |
| Автоматическая отправка напоминаний через API | Платные маркетинговые шаблоны и риск жалоб; оставляем ручную отправку (D-12) |
| Свободный ИИ-диалог бота | Ошибки в цене и дате дорогие; правила Meta ограничивают ИИ-ассистентов общего назначения (D-05) |
| Автоподтверждение оплаты по QR через платёжного провайдера | Нужны договор и API провайдера; сначала ручная проверка чека (D-09) |
| Звонки из CRM, групповые чаты, статусы WhatsApp | Нет в API или сложно и не нужно для заказов |
| Самостоятельная регистрация магазинов и оплата подписки Tapme | Первые 5–10 магазинов подключаем сами (D-20) |
| Склад, остатки, себестоимость | Партнёр работает как оптовик без склада; вместо остатков — букеты дня (D-07) |
| Каталог WhatsApp Commerce (карточки товаров Meta) | Требует Commerce Manager; букеты дня показываем фото + списком |
| Кыргызский язык интерфейса и бота | Отдельная задача после пилота (Q-08) |

## 4. Роли и права

Роли прежние: владелец, менеджер, флорист, курьер. Добавляется **область точек**
у сотрудника (см. [01-multi-point.md](01-multi-point.md)) и внутренняя роль Tapme.

| Действие | Владелец | Менеджер | Флорист | Курьер |
| --- | --- | --- | --- | --- |
| Видеть все точки компании, переключатель «Все точки» | да | только свои точки | нет | нет |
| Клиенты (вся база компании), карточка, объединение | да | да (вся база) | нет | нет |
| Чаты: читать и отвечать | да | да (свои точки и неназначенные) | нет | нет |
| Черновики заказов и заказы «Ждёт подтверждения» | да | да | нет | нет |
| Подтвердить оплату по чеку | да | да | нет | нет |
| Подтверждённые заказы своей точки | да | да | задания на сборку | доставки |
| Букеты дня: загрузить, изменить цену, «Продан в магазине» | да | да | да (своя точка) | нет |
| Настройки: Компания, Точки, Каналы, Бот | да | просмотр | нет | нет |
| Настройки: Команда, приглашения | да | нет | нет | нет |
| Настройки напоминаний (сценарии) | да | просмотр | нет | нет |
| Очередь напоминаний | да (все точки) | своя точка | нет | нет |
| Чек-лист «Подключение» | да | нет | нет | нет |

Флорист и курьер по-прежнему **не видят** базу клиентов, переписку и финансы
заказов. Единственное новое исключение для флориста — публичная цена букета дня
своей точки (FR-BQ-001, FR-BQ-010): её можно задать при публикации готового букета.
Это не даёт доступа к оплатам, выручке и суммам заказов; курьер цену не видит.

**Внутренняя роль «Поддержка Tapme»** (P1): видит статус подключения и здоровье
каналов всех компаний через админку Django; не видит переписку и клиентов.

## 5. Персоны

- **Бермет — владелец**, 2 точки. Хочет видеть все заказы и деньги, боится за номер.
- **Айгуль — менеджер точки.** Целый день в чатах, принимает заказы, проверяет оплату.
  Работает с компьютера и телефона.
- **Алина — флорист.** Утром фотографирует букеты дня, собирает заказы, отмечает «Собран».
- **Бакыт — курьер обеих точек.** Видит свои доставки, адрес и телефон получателя.
- **Покупатель** пишет в WhatsApp или Instagram, хочет быстро выбрать, оплатить и
  не повторять детали.

## 7. Итоги ревью (что было упущено и добавлено в ТЗ)

Обсуждение покрыло каналы, бота, CRM, напоминания, точки и подключение. При
ревью найдены пробелы. Все они закрыты требованиями в файлах ТЗ:

1. **Где «живут» деньги до подтверждения.** Оплаты в системе привязаны к заказу,
   а черновик — не заказ. Решение: статус `pending` «Ждёт подтверждения», невидимый
   флористу и курьеру; бронь букета и оплата привязываются к нему (D-22, FR-OD-020…).
2. **Клиент без телефона.** Сейчас телефон клиента обязателен и уникален в компании,
   а у клиента из Instagram телефона нет. Нужны идентичности каналов (D-23, FR-CR-001…).
3. **Совпадение с существующей базой.** Входящий номер WhatsApp сравнивается с
   телефонами клиентов (включая дополнительные), чтобы не плодить дубли (FR-CR-002).
4. **Ответы на ручные напоминания уходят мимо CRM.** Напоминание отправляется с
   телефона сотрудника (обычно с основного номера), ответ туда же и возвращается.
   Решение: ссылка на номер для заказов в тексте и ручные отметки (D-24, FR-RM-008).
5. **Согласие на сообщения у клиентов из чатов.** Автосозданный клиент не давал
   согласия на напоминания. Бот спрашивает согласие после заказа; запись согласия
   хранит источник и время (FR-BT-090, NFR-PR-002).
6. **Подготовка у Meta — самый долгий путь.** Tapme должен стать техническим
   провайдером Meta (проверка бизнеса, проверка приложения) или работать через
   посредника. Это недели — отдельная задача на старте (S-01, R-01).
7. **Политика конфиденциальности и условия** на домене Tapme обязательны для
   приложения Meta (NFR-PR-001).
8. **Реальное время требует ASGI.** Сейчас Gunicorn в синхронном режиме; поток
   событий для браузера требует асинхронного сервера (FR-NT-010, NFR-IN-002).
9. **Шаблоны WhatsApp для сообщений по статусам** («Оплата получена», «Курьер в
   пути», «Доставлено») — их нужно создать и одобрить у Meta, иначе после 24 часов
   клиенту не написать (FR-CH-060…, FR-PY-040).
10. **Фото-референсы от клиента** («хочу как на фото») должны попадать в черновик и
    в задание флористу (FR-OD-014).
11. **Продажа букета дня в магазине** без бота: флорист одним касанием отмечает
    «Продан в магазине», иначе бот предложит уже проданный букет (FR-BQ-012).
12. **Приглашение сотрудников по ссылке** вместо паролей, которые задаёт владелец
    (FR-ON-020).
13. **Уход сотрудника**: его чаты и клиенты нужно передать другому (FR-CR-034).
14. **Отказ клиента от сообщений** («СТОП») на номере для заказов (FR-CH-075).
15. **Голосовые и геолокация** от клиента (FR-CH-031, FR-OD-015).
16. **Пиковые дни** (8 Марта, 14 февраля): лимиты окон и поведение бота при нехватке
    мест (FR-BT-061, P2 «режим пика»).
17. **Аналитика для владельца** по каналам и скорости ответа (FR-CR-070, P1).
18. **Наблюдаемость**: ошибки вебхуков, очередь отправки, расход Meta (NFR-OB-…).

## 8. Глоссарий

| Термин | Значение |
| --- | --- |
| Компания | Бизнес-аккаунт Tapme (модель `Business`). Одна марка магазина |
| Точка | Торговая точка компании (модель `Shop`, станет «точкой»): адрес, часы, окна доставки, команда |
| Основной номер | Существующий WhatsApp магазина на телефоне. Не подключается |
| Номер для заказов | Отдельный номер на WhatsApp Cloud API, на котором работают бот и менеджеры из CRM |
| Канал | Подключённый источник переписки: номер для заказов или аккаунт Instagram |
| Идентичность | Запись «кто это в канале»: `wa_id` (номер) или Instagram-ID с ником |
| Разговор (чат) | Переписка одного собеседника в одном канале |
| Окно 24 часа | Время после последнего сообщения клиента, когда разрешён свободный ответ; тарифы проверяются отдельно |
| Шаблон Meta | Заранее одобренное Meta сообщение; способ написать после окна в WhatsApp; к Instagram это правило не относится |
| Черновик заказа | Собираемый по переписке набор полей заказа; ещё не заказ |
| Ждёт подтверждения | Статус заказа `pending`: создан, но не подтверждён менеджером (обычно ждёт оплату) |
| Букет дня | Готовый букет с фото и ценой, существующий в одном экземпляре на точке |
| Этап клиента | Новый / В диалоге / Заказал / Постоянный / Давно не был |
| Ответственный | Сотрудник, закреплённый за клиентом и его чатами |
