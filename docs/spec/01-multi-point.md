# 01. Компания и несколько точек

Решения: D-17, D-18. Макет: `design-onboarding/png/3-points.png`, переключатель
точек внизу бокового меню на всех макетах `design-onboarding/`.

## 1. Цель

Одна марка с несколькими адресами работает в одной компании Tapme: общая база
клиентов, прайс, чаты и напоминания; у каждой точки свои заказы, окна и зоны
доставки, букеты дня, QR для оплаты и команда. Владелец переключается между точками
и видит сводку «Все точки». Магазины с одной точкой не видят никаких изменений,
кроме вкладки «Точки» в настройках.

## 2. Текущее состояние (важно для реализации)

- `Business` — граница изоляции данных (компания). У неё ровно одна `Shop`
  (`OneToOneField`) с адресом, телефоном, часами, `delivery_windows` (JSON),
  `pickup_unlimited`, `enforce_capacity`.
- `OrderRecord` не знает точку. Номер заказа — счётчик `OrderCounter` на `Business`.
- `DeliverySlots` блокирует строку магазина при резервировании окна.
- Переключатель бизнесов уже есть (`App.tsx`, `<select aria-label="Магазин">`),
  он переключает **компании**. Переключатель **точек** — новый и живёт рядом.

## 3. Пользовательские истории

- US-MP-1. Как владелец двух точек, я хочу видеть заказы и выручку каждой точки
  отдельно и вместе, чтобы понимать, где что происходит.
- US-MP-2. Как менеджер точки «Токтогула», я хочу видеть только заказы своей
  точки, но узнавать любого клиента компании, чтобы не спрашивать постоянного
  клиента заново, даже если он раньше покупал на другой точке.
- US-MP-3. Как курьер обеих точек, я хочу видеть доставки с обеих точек с пометкой,
  откуда забрать букет.
- US-MP-4. Как владелец, я хочу настроить у каждой точки адрес, часы, окна,
  зоны доставки, QR и команду.
- US-MP-5. Как владелец магазина с одной точкой, я не хочу видеть лишних
  переключателей.

## 4. Модель данных

### 4.1. Точка (`businesses.Shop`)

Имя модели сохраняем (`Shop`), в API и интерфейсе — «точка» (`point`).

| Поле | Тип | Изменение | Описание |
| --- | --- | --- | --- |
| `business` | FK → `Business` | **было OneToOne** | `related_name="points"`, `on_delete=PROTECT` |
| `is_primary` | bool | новое | Ровно одна основная точка на компанию (частичный уникальный индекс `business` где `is_primary`) |
| `active` | bool | новое, по умолчанию `true` | Архивная точка не принимает новые заказы |
| `short_name` | str(40) | новое | Короткое имя для бейджей и бота: «Токтогула» |
| `payment_qr_key` | str(500), пусто | новое | Ключ фото QR в закрытом хранилище (`PhotoStorage`) |
| `payment_note` | str(300), пусто | новое | Текст к QR: банк, получатель, например «MBank · Бермет У.» |
| `sort` | int | новое | Порядок в списках |
| прочие поля | — | без изменений | `address`, `phone`, `city`, `whatsapp`, `opening_hours`, `delivery_windows`, `pickup_unlimited`, `enforce_capacity`, `version` |

Часы работы для бота храним структурированно (P0): новое поле `hours` (JSON):
`{"mon": [["09:00","21:00"]], …, "sun": [...]}`. Текстовое `opening_hours` остаётся
для показа и заполняется из `hours`, если не задано вручную.

### 4.2. Зона доставки (`businesses.DeliveryZone`, новая)

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | UUID | |
| `point` | FK → `Shop` | |
| `name` | str(120) | «Центр (до 3 км)» |
| `price` | Decimal(12,2) | Стоимость доставки в сомах |
| `eta_minutes` | int, пусто | Ориентировочное время доставки, для подсказок |
| `active` | bool | |
| `sort` | int | |

Стоимость доставки заказа = `zone.price` + надбавка окна (`delivery_windows[i].price`,
если задана). Снимок суммы хранится в заказе (`delivery_fee`), как сейчас.
Поле `OrderRecord.delivery_zone_name` (новое, str 120) хранит снимок названия зоны.

### 4.3. Область точек сотрудника

Новая таблица `businesses.MembershipPoint(membership FK, point FK)`, уникальная пара.

- Пустой набор у владельца и менеджера означает «все точки».
- Флорист и курьер должны иметь хотя бы одну точку, если в компании больше одной
  точки; при одной точке набор пустой = эта точка.
- Владелец всегда видит все точки, независимо от набора.

### 4.4. Привязка данных к точке

| Модель | Поле | Обязательность | Правило |
| --- | --- | --- | --- |
| `orders.OrderRecord` | `point` FK | обязательно | Задаётся при создании, меняется только через «Перенести на другую точку» |
| `orders.OfficeTask` | `point` FK | пусто = задача всей компании | |
| `reminders.ReminderRecord` | `point` FK | пусто | Точка последнего заказа клиента; если заказов нет — основная точка |
| `messaging.Conversation` | `point` FK | пусто | См. [04](04-chats-and-crm.md); выставляется при выборе точки в боте или менеджером |
| `catalog.BouquetOfDay` | `point` FK | обязательно | См. [06](06-bot-and-bouquets.md) |

**Общими на компанию остаются:** клиенты, получатели, важные даты, прайс,
настройки напоминаний и шаблоны, каналы, бот, счётчики номеров заказов и клиентов.

### 4.5. Миграция существующих данных

1. Для каждой `Business` её единственная `Shop` становится `is_primary=true`,
   `active=true`, `short_name` = первые слова адреса или «Основная».
2. Все `OrderRecord.point` = основная точка компании.
3. Все `ReminderRecord.point` = точка последнего заказа клиента или основная.
4. `MembershipPoint` не создаются (пустой набор = все точки).
5. Миграция идёт в одной транзакции на компанию; повторный запуск не меняет данные.
6. После миграции все существующие тесты проходят без изменений поведения для
   компаний с одной точкой.

## 5. API

Все пути начинаются с `/api/v1/businesses/{business_id}/`.

| Метод и путь | Кто | Описание |
| --- | --- | --- |
| `GET points/` | все роли (только доступные точки) | Список точек: `id, short_name, address, is_primary, active, sort` |
| `POST points/` | владелец | Создать точку |
| `GET points/{point_id}/` | владелец, менеджер этой точки | Полные настройки точки |
| `PATCH points/{point_id}/` | владелец | Изменить; передаётся `version`, конфликт → 409 |
| `POST points/{point_id}/archive/` | владелец | Архивировать (см. FR-MP-014) |
| `GET/POST points/{point_id}/zones/`, `PATCH/DELETE …/zones/{zone_id}/` | владелец | Зоны доставки |
| `PUT points/{point_id}/payment-qr/` | владелец | Загрузить картинку QR (PNG/JPEG/WebP до 5 МБ) |
| `GET points/{point_id}/payment-qr/` | владелец, менеджер | Получить картинку QR (закрытая, через сессию) |
| `GET company/`, `PATCH company/` | владелец (чтение — менеджер) | Название, часовой пояс, валюта, правила предоплаты (см. [05](05-order-draft-and-payments.md)) |

Существующие эндпоинты заказов, задач, сводки, доставок и календаря получают
параметр `point`:

- `point=<uuid>` — одна точка; 403, если точка недоступна пользователю.
- `point=all` — все доступные пользователю точки (владелец — все; менеджер —
  объединение своих).
- Без параметра — все доступные (обратная совместимость).

`GET settings/` (старый эндпоинт магазина) один релиз продолжает работать и
возвращает основную точку; в OpenAPI помечается `deprecated`.

## 6. Интерфейс

- **Переключатель точек** внизу бокового меню: подпись «Точка», кнопка с иконкой
  метки и названием («Все точки», «Токтогула»…), список доступных точек.
  Выбор сохраняется в `localStorage` на пользователя и компанию и добавляется в
  адрес страницы (`&point=`). Если доступна одна точка — переключатель скрыт.
- **Режим «Все точки»:** на карточках заказов, в списке доставок, задачах и
  календаре — бейдж с `short_name` точки. В сводке («заказов», «выручка» и т. д.)
  — сумма по точкам; по наведению или в развороте — разбивка по точкам (P1).
- **Форма заказа:** поле «Точка». По умолчанию — выбранная точка; в режиме
  «Все точки» поле обязательно и пустое. Окна доставки и зоны берутся у выбранной точки.
- **Настройки → «Точки»** (по макету): слева список точек с меткой «основная» и
  числом сотрудников, «Добавить точку», пояснение про общие и раздельные данные;
  справа редактор: адрес, часы работы (по дням), телефон точки, окна доставки
  с лимитом, зоны доставки (название, цена, время), QR для оплаты, команда точки.
- **Настройки → «Окна доставки»** как отдельная вкладка удаляется: окна теперь
  внутри «Точек».
- **Карточка заказа:** строка «Точка: Токтогула» и действие «Перенести на другую точку».

## 7. Функциональные требования

### FR-MP-001 (P0). Несколько точек в компании
Владелец создаёт вторую и следующие точки. Ровно одна точка основная.
- Дано компанию с одной точкой, когда владелец создаёт точку «Чуй», тогда в
  `GET points/` две точки и только одна `is_primary=true`.
- Когда владелец делает основной другую точку, тогда флаг у прежней снимается
  в той же транзакции.
- Попытка менеджера, флориста или курьера создать точку → 403.

### FR-MP-002 (P0). Область точек сотрудника
- Владелец назначает сотруднику одну, несколько или все точки (Настройки → Команда
  и Точки → «Команда точки»).
- Флорист или курьер без точки в компании с несколькими точками не может войти в
  рабочий экран и видит сообщение «Владелец ещё не назначил вам точку».
- Изменение области вступает в силу со следующего запроса (без повторного входа).

### FR-MP-003 (P0). Заказ привязан к точке
- Каждый новый заказ получает `point`; создание без точки в компании с несколькими
  точками → 400 с полем `point`.
- Окно доставки и вместимость проверяются по окнам выбранной точки; блокируется
  строка этой точки (как сейчас — строка магазина).
- Номер заказа сквозной по компании: два заказа на разных точках не получают
  одинаковый номер. Проверяется тестом с одновременным созданием.

### FR-MP-004 (P0). Видимость заказов по точкам
- Менеджер с точкой A не видит заказы точки B ни в списке, ни в поиске, ни по
  прямому `GET orders/{id}/` (404, как для чужой компании).
- Флорист видит задания и свободные новые заказы только своих точек.
- Курьер видит доставки своих точек; в списке у каждой доставки — точка, откуда
  забрать букет.
- Владелец видит всё.

### FR-MP-005 (P0). Клиенты общие
- Менеджер любой точки находит любого клиента компании и видит его заказы со всех
  точек **без сумм заказов чужих точек** (номер, дата, точка, статус, состав);
  владелец видит суммы.
- Создание клиента на одной точке не создаёт дубль на другой (уникальность телефона
  остаётся на уровне компании).

### FR-MP-006 (P0). Переключатель точек
- При двух и более доступных точках внизу меню показывается переключатель с
  пунктами каждой точки и «Все точки» (если доступно больше одной).
- Выбор меняет данные на экранах Заказы, Доставка, сводка, Задачи, Напоминания,
  Букеты дня без перезагрузки страницы и сохраняется после перезагрузки.
- При одной точке переключатель и бейджи точек не показываются.

### FR-MP-007 (P0). Зоны доставки
- Владелец добавляет, изменяет, выключает и упорядочивает зоны точки.
- В форме заказа с доставкой выбирается зона; `delivery_fee` = цена зоны + надбавка окна.
- Выключенная зона не предлагается в новых заказах и в боте; в старых заказах
  остаётся снимок названия и цены.

### FR-MP-008 (P0). QR для оплаты у точки
- Владелец загружает картинку QR и подпись к ней. Картинка хранится в закрытом
  хранилище, проходит ту же проверку и очистку метаданных, что фото заказов.
- Если у точки нет QR, бот и кнопка «Отправить QR» показывают понятную ошибку и
  не отправляют пустое сообщение; чек-лист «Подключение» отмечает шаг «Оплата»
  невыполненным.

### FR-MP-009 (P0). Часы работы точки
- Часы задаются по дням недели; допускается выходной день и несколько интервалов.
- Бот и уведомления используют эти часы для режима «вне рабочего времени»
  (см. [06](06-bot-and-bouquets.md), [02](02-notifications.md)).

### FR-MP-010 (P0). Миграция без изменения поведения
- После миграции компания с одной точкой работает как раньше: те же экраны, те же
  данные, все существующие тесты проходят.

### FR-MP-011 (P1). Сводка по точкам
- В режиме «Все точки» показатели сводки раскрываются по точкам (таблица или
  всплывающая подсказка). Суммы считает сервер.

### FR-MP-012 (P1). Перенос заказа на другую точку
- Владелец или менеджер обеих точек переносит заказ в статусе `pending` или `new`
  на другую точку. Окно пересчитывается по окнам новой точки (с проверкой
  вместимости), цена доставки — по зоне новой точки с подтверждением суммы.
- В истории заказа — событие «Перенесён с Токтогула на Чуй».
- После статуса `work` перенос запрещён (409 с понятной причиной).

### FR-MP-013 (P1). Задачи офиса по точкам
- Задача может принадлежать точке или всей компании; фильтр как у заказов.

### FR-MP-014 (P0). Архивирование точки
- Нельзя архивировать основную точку и точку с незавершёнными заказами
  (`pending`, `new`, `work`, `ready`, `route`) — 409 со списком номеров.
- Архивная точка не показывается в форме заказа, в боте и в переключателе;
  её заказы остаются в истории и отчётах.

## 8. Граничные случаи

- Курьер обеих точек: в «Мои доставки» — обе точки, сортировка по окну.
- Сотрудник удалён из точки, у него назначенные заказы этой точки — запрет с тем же
  правилом, что при удалении из магазина (передать или завершить).
- Время работы точки пересекает полночь — не поддерживается в P0; интервал
  ограничен одним днём.
- Компания меняет часовой пояс — все точки в одном часовом поясе (P2: разные
  пояса не поддерживаем).

## 9. Тесты (минимум)

- Изоляция: менеджер точки A не читает и не изменяет заказ точки B (список, поиск,
  деталь, оплата, фото, история, экспорт).
- Одновременное создание заказов на двух точках не даёт одинаковых номеров.
- Последнее место в окне точки не продаётся дважды (существующий тест расширить на точки).
- Миграция на копии базы с демо-данными: число заказов и суммы не меняются.
- Переключатель: Playwright — выбор точки меняет список заказов, сохраняется после
  перезагрузки, скрыт при одной точке.
