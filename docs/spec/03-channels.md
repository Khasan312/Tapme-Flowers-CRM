# 03. Каналы: WhatsApp Cloud API и Instagram Direct

Решения: D-01, D-02, D-03, D-11, D-19, D-21. Макеты: `design-onboarding/png/2-channels.png`,
`design-onboarding/png/1-setup.png` (шаг WhatsApp).

## 1. Цель

Подключить к компании **номер для заказов** (WhatsApp Cloud API) и **Instagram
Direct** так, чтобы все входящие сообщения попадали в CRM за секунды, а ответы из
CRM доходили клиенту, без риска для основного номера магазина.

## 2. Что нужно у Meta до разработки (задача S-01)

Это самый долгий путь релиза, он идёт параллельно разработке с первого дня.

1. **Приложение Meta для Tapme** (тип Business) в аккаунте разработчика Tapme.
2. **Проверка бизнеса Tapme** в Meta Business (документы компании Tapme).
3. **Политика конфиденциальности и условия использования** на домене Tapme
   (NFR-PR-001) — требуются для приложения.
4. **WhatsApp:** путь A — Tapme становится техническим провайдером Meta (Tech Provider):
   встроенная регистрация (Embedded Signup) с журналированием сессии, проверка
   приложения на разрешения `whatsapp_business_management` и
   `whatsapp_business_messaging`. Путь B — через партнёра-посредника (BSP),
   который уже провайдер, если путь A займёт больше 3 недель. Решение — Q-01.
5. **Instagram:** «Instagram API со входом через Instagram» (без страницы Facebook),
   разрешения `instagram_business_basic`, `instagram_business_manage_messages`.
   На пилоте аккаунт магазина добавляется тестировщиком приложения — проверка
   приложения не нужна, пока аккаунтов мало. Проверить в S-02.
6. **Для магазина:** новая SIM-карта на магазин (номер не зарегистрирован в
   WhatsApp), аккаунт Facebook владельца, бизнес-аккаунт Meta магазина, способ
   оплаты в Meta для шаблонов, профессиональный аккаунт Instagram.

Результат S-01 — записанная пошаговая инструкция подключения в
`docs/runbooks/meta-onboarding.md` и рабочее тестовое подключение (тестовый номер
Meta и тестовый аккаунт Instagram).

## 3. Новый модуль `messaging`

### 3.1. Модель данных

`messaging.ChannelAccount` — подключённый канал компании.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | UUID | |
| `business` | FK | |
| `kind` | `whatsapp` \| `instagram` | |
| `status` | `connecting` \| `pending_review` \| `active` \| `error` \| `disconnected` | |
| `display_name` | str | Имя у клиентов («Tapme Flowers · заказы») или ник Instagram |
| `display_phone` | str | Номер для заказов в формате `+996…` (WhatsApp) |
| `waba_id`, `phone_number_id` | str | Идентификаторы WhatsApp (уникальны глобально) |
| `ig_user_id`, `ig_username` | str | Идентификаторы Instagram (уникальны глобально) |
| `name_status` | str | Статус проверки имени у Meta |
| `quality_rating` | `green` \| `yellow` \| `red` \| пусто | Оценка качества номера |
| `messaging_limit` | str | Текущий лимит сообщений по инициативе бизнеса |
| `last_webhook_at` | datetime | Последний принятый вебхук |
| `connected_at`, `connected_by` | | |
| `settings` | JSON | Флаги канала (например, `auto_mark_read`) |

Уникальность: у компании не больше одного активного канала каждого вида (P0).
Несколько номеров для заказов (по точкам) — P2.

`messaging.ChannelCredential` — секреты отдельно от канала.

| Поле | Описание |
| --- | --- |
| `channel` | FK, один к одному |
| `token_encrypted` | Токен доступа, зашифрованный ключом из `TAPME_SECRETS_KEY` (Fernet/AES-GCM) |
| `token_expires_at` | Для токенов Instagram (долгоживущий токен обновляется задачей) |
| `scopes` | Выданные разрешения |

Токен никогда не возвращается API и не пишется в логи; в админке Django — только
маска и дата.

`messaging.WebhookEvent` — сырые входящие вебхуки.

| Поле | Описание |
| --- | --- |
| `id` | UUID |
| `source` | `whatsapp` \| `instagram` |
| `received_at`, `processed_at` | |
| `signature_ok` | bool |
| `payload` | JSON (сырое тело) |
| `dedupe_key` | SHA-256 тела; уникальный |
| `status` | `new` \| `done` \| `failed` \| `ignored` |
| `error` | текст ошибки обработки |

Хранится 30 дней, затем удаляется задачей очистки (NFR-PR-006).

Разговоры, сообщения и идентичности описаны в [04-chats-and-crm.md](04-chats-and-crm.md)
(модели `Conversation`, `Message`, `ChannelIdentity`); этот файл задаёт, как они
наполняются из каналов и как сообщения уходят наружу.

`messaging.MessageTemplate` — шаблоны WhatsApp компании.

| Поле | Описание |
| --- | --- |
| `channel` | FK |
| `name`, `language` | Имя шаблона у Meta и язык (`ru`) |
| `category` | `utility` \| `marketing` \| `authentication` (как у Meta, может быть изменена Meta) |
| `status` | `pending` \| `approved` \| `rejected` \| `paused` \| `disabled` |
| `purpose` | Назначение в Tapme: `order_confirmed`, `payment_received`, `order_ready_pickup`, `courier_on_way`, `order_delivered`, `generic_followup` |
| `body`, `params` | Текст и список подстановок |
| `rejected_reason` | |
| `synced_at` | |

### 3.2. Шифрование и ключи

- `TAPME_SECRETS_KEY` — ключ шифрования токенов (в `.env`, не в Git). Ротация —
  команда `rotate_channel_secrets` перешифровывает все записи (P1).
- `META_APP_ID`, `META_APP_SECRET`, `META_WEBHOOK_VERIFY_TOKEN`,
  `META_CONFIG_ID` (конфигурация Embedded Signup) — переменные окружения.
- Без этих переменных модуль каналов выключен: экран «Каналы» показывает «Каналы
  не настроены на сервере», остальная CRM работает.

## 4. Подключение

### FR-CH-001 (P0). Подключение номера для заказов (WhatsApp)
Кнопка «Подключить» в шаге «Подключение» и в Настройки → Каналы открывает окно
встроенной регистрации Meta. Владелец входит в Facebook, выбирает или создаёт
бизнес-аккаунт Meta **магазина**, вводит номер для заказов, подтверждает код из SMS,
вводит имя для клиентов.
- По завершении сервер получает код и идентификаторы (WABA, номер), обменивает код на
  токен, подписывает приложение Tapme на вебхуки WABA, регистрирует номер для Cloud API
  (с шестизначным PIN двухэтапной проверки, PIN хранится зашифрованно), сохраняет
  `ChannelAccount` со статусом `pending_review` или `active`.
- Шаги отражаются в чек-листе: «Номер подтверждён кодом из SMS», «Бизнес-аккаунт Meta
  создан на магазин», «Имя на проверке Meta».
- Если окно закрыто без завершения — канал остаётся `connecting`, кнопка «Продолжить
  подключение».
- Подключение доступно только владельцу; менеджер видит статус.
- Повторное подключение того же номера к другой компании Tapme → ошибка «Этот
  номер уже подключён к другому магазину Tapme».

### FR-CH-002 (P0). Подключение Instagram
Кнопка «Подключить Instagram» открывает вход через Instagram. Владелец входит в
профессиональный аккаунт магазина и выдаёт разрешения.
- Сервер обменивает код на долгоживущий токен, подписывает аккаунт на вебхуки
  сообщений, сохраняет `ChannelAccount(kind=instagram, status=active)`.
- Если аккаунт личный (не профессиональный) — понятная ошибка со ссылкой на
  инструкцию «Как переключить на профессиональный аккаунт».
- Задача Celery обновляет токен до истечения срока (за 10 дней); при неудаче —
  `channel.alert` владельцу.

### FR-CH-003 (P0). Основной номер — только автоответ
Канал «Главный номер магазина» не подключается. Экран показывает его номер (из
настроек основной точки), статус «Не подключается» и пояснение «Остаётся только на
телефоне — CRM его не читает и с него не пишет. Так номер защищён от блокировки».
- Текст автоответа со ссылкой `wa.me/<номер для заказов>` генерируется из имени
  компании и номера для заказов; кнопки «Скопировать» и «Готово, вставил» (отметка
  с датой хранится в настройках компании).

### FR-CH-004 (P0). Отключение канала
Владелец нажимает «Отключить» → подтверждение «Новые сообщения перестанут приходить в
CRM. Переписка сохранится» → сервер отписывает приложение от вебхуков (если возможно),
удаляет токен, ставит `disconnected`. Разговоры остаются для чтения; отправка
недоступна с пояснением.

## 5. Приём сообщений

### FR-CH-010 (P0). Эндпоинты вебхуков
- `GET /api/v1/webhooks/meta/whatsapp/` и `/instagram/` — проверка подписки:
  при совпадении `hub.verify_token` возвращают `hub.challenge`, иначе 403.
- `POST` на те же пути — без сессии и CSRF (исключение), с проверкой подписи
  `X-Hub-Signature-256` (HMAC-SHA256 тела с `META_APP_SECRET`, сравнение в постоянное
  время). Неверная подпись → 401, событие сохраняется с `signature_ok=false` для
  разбора, но не обрабатывается.
- Тело сохраняется в `WebhookEvent`, ставится задача обработки, ответ 200 —
  не дольше 1 секунды (p95 ≤ 300 мс). Обработка никогда не идёт внутри запроса.
- Повтор того же тела (Meta повторяет при ошибках) не обрабатывается дважды
  (`dedupe_key`), и каждое сообщение уникально по внешнему ID (см. FR-CH-012).

### FR-CH-011 (P0). Разбор событий WhatsApp
Обрабатываются поля вебхука:
- `messages` — входящие сообщения: `text`, `image`, `audio` (включая голосовые),
  `video`, `document`, `location`, `contacts`, `sticker`, `reaction`,
  `interactive` (`button_reply`, `list_reply` — ответы на кнопки бота), `button`
  (быстрый ответ на шаблон). Тип `unsupported` или неизвестный сохраняется как
  сообщение «Клиент отправил сообщение, которое пока не поддерживается» с типом.
- `contacts[].profile.name` — имя профиля WhatsApp, сохраняется в идентичность как
  «имя в WhatsApp» (не перезаписывает имя клиента, введённое менеджером).
- `statuses` — статусы исходящих: `sent`, `delivered`, `read`, `failed` с кодом и
  текстом ошибки; блок `pricing` (платное ли сообщение, категория) сохраняется для
  учёта расходов (FR-CH-080).
- Обновления шаблонов (`message_template_status_update`), качества номера
  (`phone_number_quality_update`), аккаунта (`account_update` и т. п.) — обновляют
  `MessageTemplate` и `ChannelAccount`, при ухудшении — `channel.alert`.

### FR-CH-012 (P0). Идемпотентность и порядок
- Сообщение уникально по `(channel, external_id)` (`wamid` для WhatsApp, `mid` для
  Instagram). Повторный вебхук не создаёт второе сообщение и второе уведомление.
- Порядок в чате строится по времени отправки из вебхука (`timestamp`), а не по
  времени получения. Опоздавший статус (`delivered` после `read`) не понижает статус.
- Статус для ещё не записанного исходящего (гонка) откладывается и применяется,
  когда запись появится (повтор задачи до 5 минут).

### FR-CH-013 (P0). Медиа
- Для входящих медиа сервер получает временную ссылку по ID медиа и скачивает файл
  с токеном канала в фоновой задаче сразу после записи сообщения (ссылки
  короткоживущие). Текст сообщения показывается сразу, медиа — по готовности.
- Изображения проходят ту же обработку, что фото заказов (Pillow, очистка
  метаданных, JPEG), и хранятся в закрытом хранилище с ключами `messages/…`.
- Аудио, видео и документы хранятся как есть; лимит на файл — 16 МБ, больше —
  сообщение с пометкой «Файл слишком большой, откройте у клиента запрос повторить».
- Чтение медиа — только через API с сессией и проверкой роли (флорист и курьер —
  только фото-референсы, прикреплённые к их заказу, см. FR-OD-014).

### FR-CH-014 (P0). Разбор событий Instagram
- Входящие сообщения (`messages`): текст, изображения, видео, аудио, ответы на сторис,
  упоминания в сторис, реакции, ответы на быстрые кнопки (`quick_reply`), нажатия
  кнопок шаблона (`postback`).
- Эхо (`is_echo: true`) — сообщения, отправленные бизнесом. Если эхо относится к
  сообщению, отправленному из CRM (совпадает `mid`), — только обновление статуса.
  Если отправлено из приложения Instagram — сохраняется как исходящее с отправителем
  «Из приложения Instagram» (проверить поведение в S-02).
- Прочтение (`messaging_seen`) обновляет статус исходящих до `read`.
- Имя и ник собеседника запрашиваются через API профиля один раз при первом сообщении
  и раз в 7 дней.

## 6. Отправка сообщений

### FR-CH-020 (P0). Исходящая очередь
- Любое исходящее (из CRM, от бота, по статусу заказа) сначала записывается как
  `Message(direction=out, status=queued)` в транзакции вместе с действием, которое его
  вызвало (outbox). Отправку выполняет задача Celery (очередь `outbound`).
- Повтор при сетевых ошибках и 5xx — до 5 раз с экспоненциальной паузой (1, 4, 15,
  60, 240 секунд). Ошибки 4xx не повторяются, сообщение получает `failed` с кодом и
  понятным текстом.
- Ответ API с внешним ID записывается в сообщение (`sent`). Дальше статусы — из вебхуков.
- Ключ идемпотентности: `Message.id`; повторный вызов задачи для уже отправленного
  сообщения ничего не делает.

### FR-CH-021 (P0). Типы исходящих WhatsApp
- Текст (до 4096 символов), изображение (из хранилища — загрузка медиа в Meta по
  требованию), документ, геолокация магазина, ответ на конкретное сообщение
  (`context`), реакция, интерактивные сообщения: кнопки ответа (до 3, заголовок до 20
  символов), список (до 10 строк, заголовок строки до 24 символов), шаблон.
- Отметка «прочитано» отправляется, когда сотрудник открыл разговор (если включено
  в настройках канала; по умолчанию включено).
- Ограничения длины проверяются до отправки; бот обрезает или переносит длинные
  подписи (см. [06](06-bot-and-bouquets.md)).

### FR-CH-022 (P0). Типы исходящих Instagram
- Текст, изображение, быстрые ответы (до 13, заголовок до 20 символов), ответ на
  сообщение, реакция. Галерея карточек (generic template) — P1.

### FR-CH-030 (P0). Окно 24 часа
- У разговора хранится `last_inbound_at`. Окно открыто, если с него прошло меньше
  24 часов.
- В открытом окне любые сообщения бесплатны и без ограничений по типу.
- В закрытом окне WhatsApp: поле ввода заменяется на «Окно закрыто — клиент молчит
  больше 24 часов. Отправить шаблон:» со списком одобренных шаблонов подходящего
  назначения; свободный текст отправить нельзя.
- В закрытом окне Instagram: отправка недоступна с пояснением «Instagram разрешает
  ответить в течение 24 часов после сообщения клиента». Тег «Ответ сотрудника» (до 7
  дней) — P2, требует проверки приложения.
- Над полем ввода — индикатор «Окно открыто ещё 3 ч 12 мин» в последние 4 часа.
- Отправка в закрытое окно, пойманная на стороне Meta (ошибка «вне окна»), переводит
  сообщение в `failed` с текстом «Окно закрыто, отправьте шаблон».

### FR-CH-031 (P0). Голосовые и файлы от клиента
- Голосовые и аудио воспроизводятся встроенным плеером в чате. Видео — плеер,
  документы — ссылка «Скачать» (через API с сессией).
- Расшифровка голосовых в текст — P2.

## 7. Шаблоны WhatsApp

### FR-CH-060 (P0). Набор шаблонов по умолчанию
При подключении номера Tapme создаёт у Meta шаблоны (язык `ru`, категория
`utility`) с подстановками и сохраняет их в `MessageTemplate`:

| `purpose` | Пример текста |
| --- | --- |
| `order_confirmed` | «Заказ №{{1}} принят на {{2}}. Статус заказа: {{3}}» |
| `payment_received` | «Оплата по заказу №{{1}} получена. Спасибо!» |
| `order_ready_pickup` | «Заказ №{{1}} готов, можно забрать: {{2}}» |
| `courier_on_way` | «Курьер везёт заказ №{{1}}, ожидайте в окне {{2}}» |
| `order_delivered` | «Заказ №{{1}} вручён. Будем рады отзыву: {{2}}» |
| `generic_followup` | «Здравствуйте! Это {{1}}. Ответим на ваше сообщение здесь.» |

Тексты окончательно согласуются перед подачей (Q-06). Meta может изменить категорию
— Tapme сохраняет фактическую и показывает её.

### FR-CH-061 (P0). Синхронизация и статусы
- Статусы шаблонов обновляются из вебхуков и задачей раз в сутки.
- Отклонённый шаблон: `channel.alert` владельцу с причиной; назначение без
  одобренного шаблона отмечается в Каналах «Не отправим после 24 часов: нет шаблона».

### FR-CH-062 (P1). Просмотр и правка шаблонов
- Настройки → Каналы → «Шаблоны»: список с назначением, текстом, категорией, статусом.
  Изменение текста создаёт новую версию шаблона у Meta (старый остаётся до
  одобрения нового).

## 8. Здоровье канала и расходы

### FR-CH-070 (P0). Карточки каналов (по макету)
- **WhatsApp:** номер, имя у клиентов и статус его проверки, качество номера (шкала
  и подпись «Meta оценивает по жалобам и блокировкам клиентов. За 30 дней жалоб нет»),
  активность за сегодня (входящие, ответы, среднее время ответа), правило 24 часов и
  число одобренных шаблонов, способ оплаты Meta и оценка расходов за месяц, строка
  состояния «Связь работает · последнее сообщение 10:04», кнопки «Шаблоны» и
  «Проверить связь».
- **Instagram:** ник, что видит CRM, правило бота (24 часа), активность за сегодня,
  строка состояния, «Отключить».
- **Главный номер магазина:** FR-CH-003.
- **Уведомления о чатах:** см. [02](02-notifications.md), раздел 7.

### FR-CH-071 (P0). «Связь работает»
- Статус «работает», если канал `active` и за последние 24 часа нет ошибок
  отправки подряд больше 3, а подписка на вебхуки подтверждена.
- «Проверить связь» запрашивает у Meta данные номера/аккаунта и состояние подписки,
  показывает результат и время.
- Если вебхуков нет больше 6 часов в рабочее время, при этом исходящие уходят, —
  предупреждение «Не приходят входящие — проверьте подписку».

### FR-CH-072 (P0). Качество и лимиты
- Изменение качества (`green` → `yellow`/`red`) или лимита сообщений по инициативе
  бизнеса — `channel.alert` владельцу с понятным текстом и советом («Проверьте
  тексты сообщений, которые вы отправляете первыми»).

### FR-CH-075 (P0). Отказ от сообщений
- Входящее «стоп», «stop», «отписаться», «не пишите» (без учёта регистра, отдельным
  сообщением) отмечает идентичность `opted_out_at`. Шаблоны по инициативе магазина
  такому клиенту не отправляются; согласие на напоминания снимается с записью
  источника. Ответить в открытом окне можно.
- Бот подтверждает: «Хорошо, больше не будем писать первыми. Если понадобимся —
  просто напишите».

### FR-CH-080 (P1). Учёт расходов Meta
- По статусам с `pricing.billable=true` считается число платных сообщений по
  категориям за месяц. Цена за сообщение по категории вводится владельцем или Tapme
  из прайса Meta для группы стран (Кыргызстан — «Other»). Показывается «за октябрь ≈ $4,20».
- Это оценка, а не счёт Meta; подпись «по данным Meta о платных сообщениях».

## 9. Безопасность и соответствие правилам Meta

- Бот не является ИИ-ассистентом общего назначения: он отвечает по сценарию магазина
  (FR-BT-001). ИИ используется только внутри CRM для черновика заказа и фактов (D-05).
- Магазин не отправляет первым никаких маркетинговых сообщений через API в этом релизе.
- Все вебхуки проверяются подписью; эндпоинты вебхуков ограничены по частоте
  (NFR-SE-004).
- Токены шифруются, доступ к ним — только в адаптере канала.

## 10. Тесты

- Проверка подписи: верная, неверная, отсутствует, тело изменено.
- Набор записанных примеров вебхуков WhatsApp и Instagram (`tests/fixtures/meta/`):
  каждый тип сообщения, статусы, шаблоны, качество; повтор того же тела.
- Двойник Graph API (`FakeMetaClient`) для отправки: успех, 4xx, 5xx с повтором,
  таймаут.
- Окно 24 часа: открыто/закрыто, граница ровно 24:00:00, отправка шаблона.
- Медиа: скачивание по временной ссылке, превышение размера, ошибка скачивания с повтором.
- Изоляция: вебхук номера компании A никогда не создаёт данные в компании B (поиск
  канала по `phone_number_id`/`ig_user_id`).
