# 04. Чаты и CRM переписки

Решения: D-14, D-15, D-16, D-19, D-23. Макеты: `design-crm/png/1-chats.png`,
`2-clients.png`, `3-client-card.png`, `4-mobile.png`.

## 1. Цель

Каждый, кто написал на номер для заказов или в Instagram Direct, сразу становится
клиентом в базе. Менеджер отвечает из раздела «Чаты», видит рядом карточку клиента и
черновик заказа. В разделе «Клиенты» — вся база с этапами, каналом, последним
сообщением и ответственным. Карточка клиента показывает всю историю одной лентой.

## 2. Модель данных

### 2.1. Изменения клиента (`customers.CustomerRecord`)

| Поле | Изменение | Описание |
| --- | --- | --- |
| `phone` | **становится необязательным** | Пустая строка допустима для клиента только из Instagram. Уникальность `(business, phone)` — только для непустых (частичный индекс) |
| `origin` | новое: `manual` \| `import` \| `whatsapp` \| `instagram` \| `bot` | Как клиент попал в базу |
| `first_contact_at` | новое | Время первого сообщения или создания |
| `stage` | новое, вычисляемое и сохраняемое | `new` \| `talking` \| `ordered` \| `loyal` \| `lapsed` (раздел 4) |
| `stage_changed_at` | новое | |
| `responsible` | новое, FK → User, пусто | Ответственный (раздел 5) |
| `not_customer` | новое, bool | «Не клиент»: спам, ошиблись номером; скрыт из базы и напоминаний |
| `hidden_at` | новое, пусто | Автоскрытие «Новых» без заказа (FR-CR-024) |
| `name_confirmed` | новое, bool | `false`, пока имя взято из профиля канала и не подтверждено менеджером |
| `orders_count`, `last_order_at`, `last_message_at` | новые, денормализованные | Для быстрого списка; обновляются в сценариях заказов и сообщений |

Имя клиента для автосозданных: имя профиля WhatsApp (`profile.name`) или имя/ник
Instagram; если пусто — номер или `@ник`. Флаг `name_confirmed=false` показывает в
интерфейсе подсказку «Как зовут клиента?».

### 2.2. Идентичность канала (`messaging.ChannelIdentity`, новая)

| Поле | Описание |
| --- | --- |
| `id` | UUID |
| `business` | FK |
| `channel` | FK → `ChannelAccount` |
| `kind` | `whatsapp` \| `instagram` |
| `external_id` | `wa_id` (только цифры, с кодом страны) или Instagram-ID собеседника |
| `phone` | Для WhatsApp — нормализованный `+996…` |
| `handle`, `profile_name` | Ник Instagram, имя профиля |
| `customer` | FK → `CustomerRecord` (обязателен) |
| `opted_out_at` | Отказ от сообщений (FR-CH-075) |
| `created_at`, `last_seen_at` | |

Уникальность `(channel, external_id)`. Один клиент может иметь несколько идентичностей
(WhatsApp + Instagram).

### 2.3. Разговор (`messaging.Conversation`, новая)

| Поле | Описание |
| --- | --- |
| `id` | UUID |
| `business`, `channel`, `identity` | Уникальность `(channel, identity)` — один разговор на собеседника в канале |
| `customer` | FK, копия из идентичности для фильтров |
| `point` | FK → точка, пусто |
| `mode` | `bot` \| `human` \| `closed` |
| `assigned_to` | FK → User, пусто (обычно = `customer.responsible`) |
| `waiting_since` | Время первого неотвеченного входящего в режиме `human`; пусто, если ответили |
| `last_inbound_at`, `last_outbound_at`, `last_message_at` | |
| `last_message_preview` | до 120 символов, для списка |
| `unread_count` | Для текущего ответственного; детальная отметка прочтения — `ConversationRead(user, conversation, last_read_message)` |
| `bot_state` | JSON состояния бота (см. [06](06-bot-and-bouquets.md)) |
| `version` | Для конкурентных изменений режима и назначения |

### 2.4. Сообщение (`messaging.Message`, новая)

| Поле | Описание |
| --- | --- |
| `id` | UUID |
| `conversation` | FK |
| `direction` | `in` \| `out` |
| `sender_kind` | `customer` \| `staff` \| `bot` \| `system` \| `external_app` (эхо из приложения Instagram) |
| `sender_user` | FK → User для `staff` |
| `external_id` | `wamid`/`mid`, уникальный в канале, пусто до отправки |
| `type` | `text`, `image`, `audio`, `video`, `document`, `location`, `contacts`, `sticker`, `reaction`, `interactive`, `template`, `unsupported` |
| `text` | Текст или подпись |
| `payload` | JSON: кнопки, выбранный пункт, координаты, параметры шаблона |
| `media_key`, `media_mime`, `media_size` | Файл в закрытом хранилище |
| `reply_to` | FK → Message, пусто |
| `status` | `queued` \| `sent` \| `delivered` \| `read` \| `failed` \| `received` (для входящих) |
| `error_code`, `error_text` | |
| `sent_at` | Время по данным канала (для порядка) |
| `created_at` | |

Системные строки («Бот передал диалог · Айгуль», «Заказ №67 создан») — сообщения с
`sender_kind=system`, видимые только в CRM.

### 2.5. Быстрые ответы (`messaging.QuickReply`, новая)

`business, title, text, sort, created_by`. Подстановки как в шаблонах напоминаний
(`{имя}`, `{магазин}`, `{номер}`…).

### 2.6. Факты из переписки (`customers.CustomerFact`, новая)

`customer, kind (allergy|preference|important_date|recipient|address|note), text,
structured (JSON: месяц/день, имя получателя…), source_message FK, status
(suggested|accepted|rejected), decided_by, decided_at`.

### 2.7. Объединение клиентов

`customers.MergeSuggestion(business, a, b, reason, score, status: open|merged|dismissed)`;
`customers.MergeLog(business, kept, removed_snapshot JSON, moved counts, actor, created_at)`.

## 3. Раздел «Чаты»

### FR-CR-001 (P0). Автосоздание клиента при первом сообщении
- Дано: на номер для заказов пишет неизвестный номер. Когда сообщение обработано,
  тогда создаются `CustomerRecord(origin=whatsapp, stage=new, name=<имя профиля или
  номер>, name_confirmed=false)`, `ChannelIdentity`, `Conversation(mode=bot)` и
  `Message(direction=in)` в одной транзакции.
- То же для Instagram: клиент без телефона, имя — имя профиля или `@ник`.
- В разделе «Клиенты» запись появляется сразу (поток событий), с меткой «из чата».
- Клиент не получает согласие на напоминания автоматически (`consent=false`).

### FR-CR-002 (P0). Совпадение с существующим клиентом
- Если нормализованный номер WhatsApp совпадает с `phone` или любым из
  `additional_phones` клиента компании, идентичность привязывается к этому клиенту;
  новый клиент не создаётся. Метка «из чата» не ставится, `origin` не меняется.
- Если совпадений несколько (тот же номер у разных клиентов в дополнительных
  телефонах) — привязка к клиенту с последним заказом; создаётся `MergeSuggestion`.
- Номер нормализуется так же, как в формах (`+996` для местных номеров).

### FR-CR-003 (P0). Список разговоров (по макету)
- Слева: заголовок «Чаты», подпись «WhatsApp · Instagram», фильтры-чипы
  «Все N», «Ждут ответа N» (красный), «Ведёт бот N», «Мои N».
- Строка: аватар с бейджем канала (зелёный WhatsApp, розовый Instagram), имя или
  номер/ник, метки (`новый клиент`, `чек`), превью последнего сообщения, время,
  справа счётчик непрочитанных или состояние (`ждёт 2 мин`, `бот`).
- Сортировка: сначала «Ждут ответа» по времени ожидания, затем по последнему
  сообщению.
- Подгрузка по 50, поиск по имени, номеру, нику и тексту сообщений (P1 — по тексту).
- Менеджер видит разговоры своих точек и разговоры без точки; владелец — все.
- Закрытые разговоры (`closed`) — в фильтре «Архив» (P1).

### FR-CR-004 (P0). Окно разговора
- Шапка: аватар с каналом, имя/номер, метка «новый клиент», подпись «WhatsApp ·
  номер заказов · пишет с 10:02», ответственный (выбор для владельца/менеджера),
  меню: «Вернуть боту», «Закрыть разговор», «Открыть карточку», «Не клиент».
- Лента: входящие слева белые, ответы сотрудников справа зелёные с именем
  сотрудника, сообщения бота справа сиреневые с подписью «Бот», системные строки по
  центру. Фото — превью с открытием, голосовые — плеер, геолокация — адрес и карта-ссылка.
- Статусы исходящих: часы (в очереди), одна/две галочки, синие (прочитано), красный
  значок с текстом ошибки и «Повторить».
- Поле ввода: «Ответить в WhatsApp…» / «Ответить в Instagram…», вложение фото и
  файлов, кнопки «Отправить QR», «Букеты дня», «Шаблоны» (быстрые ответы),
  «Подсказать ответ» (P1, ИИ-подсказка, менеджер правит перед отправкой).
- Закрытое окно 24 часа — FR-CH-030.
- Новое сообщение во время прокрутки истории не дёргает ленту; появляется кнопка
  «Новые сообщения ↓».

### FR-CR-005 (P0). Режимы бот / человек
- Новый разговор начинается в режиме `bot` (если бот включён, иначе `human`).
- Переход в `human`: клиент нажал «Позвать менеджера»; бот не понял ввод дважды;
  сотрудник отправил сообщение в этот разговор; сотрудник нажал «Взять разговор».
  Системная строка «Бот передал диалог · <имя>».
- В режиме `human` бот молчит полностью, кроме автоматических сообщений по статусам
  заказа (FR-PY-040).
- «Вернуть боту» возвращает `bot` с начала меню; через 24 часа без сообщений
  разговор переходит в `closed`; новое входящее открывает его в режиме `bot`.
- `waiting_since` ставится при входящем в режиме `human` и сбрасывается при ответе
  сотрудника; по нему считается «Ждут ответа» и уведомление `chat.waiting`.

### FR-CR-006 (P0). Прочтение и счётчики
- Открытие разговора отмечает сообщения прочитанными для этого сотрудника и (если
  включено) отправляет отметку прочтения клиенту.
- Счётчик «Чаты» в меню — число разговоров `human` с `waiting_since` в доступных точках.

### FR-CR-007 (P0). Правая панель в чате
- Для нового клиента: блок «Клиент создан автоматически» с полем «Как зовут клиента?»
  (сохранение ставит `name_confirmed=true`).
- Для известного клиента: имя, этап, заказы и сумма (по правам), ближайшая важная
  дата, заметки, «Открыть карточку».
- Ниже — черновик заказа ([05](05-order-draft-and-payments.md)) и подсказки «Сохранить в
  карточку?» (FR-CR-050).

### FR-CR-008 (P0). Быстрые ответы
- Владелец и менеджер создают быстрые ответы (Настройки → Бот → «Быстрые ответы»);
  в чате кнопка «Шаблоны» вставляет текст с подстановками для правки перед отправкой.

### FR-CR-009 (P0). Отправка фото и файлов из CRM
- Фото (из компьютера, с камеры телефона), документ, геолокация точки. Проверки
  размеров и типов до отправки.

## 4. Этапы клиента

### FR-CR-010 (P0). Правила этапа
Этап вычисляется сервером при каждом событии, которое может его изменить (новое
сообщение, заказ создан/подтверждён/отменён/вручён, ежедневная задача в 03:00).
Порядок проверки — первое совпадение:

| Этап | Условие |
| --- | --- |
| `lapsed` «Давно не был» | Есть хотя бы один вручённый заказ, и последний вручённый старше `inactive_days` из настроек напоминаний (по умолчанию 90), и нет активных заказов |
| `loyal` «Постоянный» | ≥ 3 заказов не в статусе `cancelled` и не `pending` по всем точкам |
| `ordered` «Заказал» | ≥ 1 такого заказа |
| `talking` «В диалоге» | 0 заказов и (есть открытый черновик заказа или входящее за последние 7 дней с ответом сотрудника/бота) |
| `new` «Новый» | Всё остальное |

- Изменение этапа пишет `stage_changed_at` и событие в ленту карточки.
- Этап «Постоянный» сохраняется, пока клиент не ушёл в «Давно не был» (возврат —
  при новом заказе).

### FR-CR-011 (P0). Раздел «Клиенты» (по макету)
- Заголовок «Клиенты», подпись «128 клиентов · 9 новых из чатов за неделю — добавились сами».
- Вкладки этапов со счётчиками: «Все», «Новые», «В диалоге», «Заказали»,
  «Постоянные», «Давно не были»; фильтры «Канал: все / WhatsApp / Instagram / без
  канала», «Ответственный», существующие фильтры меток (VIP, корпоративные).
- Колонки: Клиент (аватар с бейджем канала, имя, телефон или `@ник`, метка «из чата»),
  Этап, Последнее сообщение (текст и время с иконкой канала), Ответственный (или
  «бот»), Заказов · сом (сумма — только владельцу и менеджеру), Ближайшая дата (с
  подписью «найдено в чате», если дата из факта).
- Строки «из чата» за последние 24 часа слегка подсвечены.
- Существующие поиск, импорт, экспорт, «Новый клиент» сохраняются.

### FR-CR-012 (P0). «Не клиент» и скрытие пустых
- «Не клиент» (в чате и карточке) ставит `not_customer=true`: клиент исчезает из
  списка (кроме фильтра «Скрытые»), не попадает в напоминания, разговор закрывается.
  Новые сообщения от него приходят в «Чаты» с меткой «не клиент» без уведомлений.
- **FR-CR-024 (P0).** Клиенты этапа «Новый» без заказов и без входящих 30 дней
  получают `hidden_at` и исчезают из «Все» (видны в «Скрытые» и поиске). Новое
  сообщение снимает скрытие.

## 5. Ответственный

### FR-CR-030 (P0). Первый ответивший
- Дано: разговор и клиент без ответственного. Когда сотрудник (владелец или менеджер)
  отправляет первое сообщение или нажимает «Взять разговор», тогда он становится
  `customer.responsible` и `conversation.assigned_to` (под блокировкой строки — два
  одновременных ответа не меняют ответственного дважды).
- Ответ бота не назначает ответственного.

### FR-CR-031 (P0). Ответственный не меняется сам
- Если ответственный есть, ответ другого сотрудника не меняет его. Системная строка
  «Ответила Тимур» видна в ленте.

### FR-CR-032 (P0). Ручное переназначение
- Владелец или менеджер выбирает ответственного в шапке чата или в карточке.
  Новый ответственный получает уведомление. Событие в ленте «Ответственный: Айгуль → Тимур».

### FR-CR-033 (P0). Куда идут уведомления
- Входящие и handoff — ответственному, если он активен и у него есть доступ к точке
  разговора; иначе — всем менеджерам точки; если точки нет — всем менеджерам компании.

### FR-CR-034 (P0). Уход сотрудника
- При удалении сотрудника из компании (или из точки) его клиенты и разговоры нужно
  передать: диалог удаления показывает «У Айгуль 37 клиентов и 4 открытых разговора» с
  выбором получателя или «Снять ответственного». Без выбора удаление не завершается
  (как сейчас с назначенными заказами).

## 6. Объединение клиентов

### FR-CR-040 (P0). Подсказки объединения
Создаются при:
- номере телефона в тексте сообщения Instagram, совпадающем с клиентом из WhatsApp
  или базы (номер нормализуется);
- совпадении нормализованного имени и одного дня первого контакта в разных каналах;
- совпадении номера в дополнительных телефонах двух клиентов (FR-CR-002).
- Баннер в «Клиентах» (по макету): «Похоже, это один человек» с описанием и кнопками
  «Это разные люди» и «Объединить». Одна подсказка за раз, самая свежая.

### FR-CR-041 (P0). Объединение
- Объединить можно из подсказки или в карточке («Объединить с…» и поиск клиента).
- Подтверждение показывает, что сохранится: имя, телефон (основной + дополнительные),
  согласие (истина, если у кого-то есть согласие с записью), метки (объединение),
  заметки (обе через разделитель), ответственный (у кого был последний ответ).
- Переносятся к оставшемуся клиенту: идентичности, разговоры, заказы, получатели,
  важные даты (дубли по `label+person+month+day` удаляются), отзывы, напоминания,
  факты. Удалённый клиент исчезает; запись в `MergeLog`.
- Объединение — одна транзакция с блокировкой обеих строк; повторное нажатие не
  ломает данные. Отмены нет (P2), поэтому подтверждение обязательно.
- Только владелец и менеджер.

## 7. Карточка клиента

### FR-CR-045 (P0). Шапка (по макету)
- Имя, этап, метки, каналы-чипы (телефон WhatsApp, `@ник` Instagram, «объединено 12 сен»),
  ответственный с выбором, кнопки «Чат» (открывает разговор в нужном канале; если
  каналов два — выбор) и «Новый заказ». Существующие «Позвонить», «Изменить»,
  «Согласие на сообщения» сохраняются.

### FR-CR-046 (P0). Лента «Всё»
- Вкладки: «Всё», «Переписка N», «Заказы N», «Получатели и даты N», «Заметки».
- «Всё» — события по дням: сообщения (сгруппированные: «Алина написала в WhatsApp» с
  цитатой первого сообщения группы; группа — сообщения с перерывом меньше 30 минут),
  напоминание отправлено, заказ создан из переписки, чек прикреплён, оплата, статусы
  заказа, отзыв/жалоба, изменение этапа и ответственного, объединение.
- «Переписка» — полная лента всех разговоров клиента (оба канала), с полем ответа
  внизу «Написать Алине в WhatsApp…».
- Существующие блоки (получатели, даты, заказы, отзывы, сообщения-напоминания)
  переносятся во вкладки без потери функций.

### FR-CR-047 (P0). Права в карточке
- Флорист и курьер карточку не видят (как сейчас).
- Менеджер видит заказы всех точек; суммы заказов чужих точек — нет (FR-MP-005).

## 8. Факты из переписки

### FR-CR-050 (P0). Подсказки «Сохранить в карточку?»
- ИИ-разбор переписки (тот же вызов, что для черновика, [05](05-order-draft-and-payments.md))
  предлагает факты: важная дата («ДР мамы — 18 октября»), аллергия/запрет («без
  лилий»), предпочтение («любит пионы»), получатель (имя, кем приходится, телефон),
  адрес.
- Подсказка показывается в правой панели чата и в карточке («Узнали из переписки»)
  со ссылкой на исходное сообщение и кнопками «Сохранить» / «Не нужно».
- «Сохранить» создаёт важную дату, получателя или строку в заметках; факт получает
  `accepted`. Ничего не сохраняется без нажатия.
- Повторная подсказка того же факта (тот же вид и текст) не создаётся.
- Запреты и аллергии после сохранения показываются флористу в задании на сборку
  (без имени клиента), например «Без лилий».

## 11. Граничные случаи

- Клиент пишет одновременно в WhatsApp и Instagram — два разговора у одного клиента
  (после объединения); в «Чатах» две строки с разными бейджами.
- Клиент сменил номер — новая идентичность; менеджер объединяет вручную.
- Клиент удалил сообщение в WhatsApp — Cloud API не присылает удаление надёжно;
  сообщение остаётся (без пометки).
- Сотрудник одновременно с ботом отвечает клиенту — сообщение сотрудника переводит
  разговор в `human` до отправки ответа бота; ответ бота, ещё не ушедший, отменяется.
- Очень длинная история (тысячи сообщений) — подгрузка страницами, без загрузки всей ленты.

## 12. Тесты

- Автосоздание: новый номер; номер совпал с основным телефоном; с дополнительным;
  совпал у двух клиентов; Instagram без телефона.
- Этапы: все пять правил и переходы, включая отмену 3-го заказа (был «Постоянный» →
  «Заказал»).
- Ответственный: гонка двух одновременных первых ответов; бот не назначает.
- Объединение: перенос всех связанных записей, дубли дат, согласие, транзакционность
  при ошибке на середине.
- Права: флорист/курьер получают 403 на все эндпоинты разговоров и клиентов; менеджер
  точки A не видит разговор точки B.
- Playwright: входящий вебхук → клиент в «Клиентах» с меткой «из чата» → ответ из CRM →
  ответственный назначен → «Не клиент» скрывает.
