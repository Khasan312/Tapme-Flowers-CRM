## Часть A. Бот

### A1. Цель и границы

Бот отвечает сразу, показывает букеты дня, собирает данные заказа кнопками и
списками, отправляет QR и передаёт разговор менеджеру по кнопке или когда не понял.
Свободного ИИ-диалога нет (D-05): бот работает по сценарию продаж магазина. Допустимость конкретного сценария и разрешения
проверяются по действующим правилам Meta в S-01 до подключения магазина.

### FR-BT-001 (P0). Движок сценария
- Детерминированный автомат состояний в доменном слое (`messaging/domain/bot.py`),
  без Django и без ИИ. Вход: состояние разговора, входящее сообщение (тип, текст,
  ID выбранной кнопки), контекст (точки, окна, зоны, букеты, часы, настройки).
  Выход: список исходящих сообщений, новое состояние, изменения черновика, события
  (handoff, создать заказ).
- Состояние хранится в `Conversation.bot_state` (JSON с версией сценария). Изменение
  сценария в коде увеличивает версию; разговор со старой версией начинает с меню.
- Кнопки и пункты списков имеют стабильные ID (`menu.bouquets`, `pick.<bouquet_id>`,
  `date.today`…); ответ клиента сопоставляется по ID, а не по тексту.
- Одно входящее → максимум 3 исходящих сообщения бота (кроме показа фото букетов).
- Ответ бота уходит не позже 3 секунд после получения вебхука (p95; цель — 10 секунд
  в G2 с запасом).

### FR-BT-002 (P0). Тексты бота
- Все тексты — в Настройки → Бот, с подстановками `{магазин}`, `{точка}`, `{часы}`,
  `{номер}`, `{сумма}`; у каждого есть текст по умолчанию (ниже). Ограничения длины
  каналов проверяются при сохранении (заголовок кнопки WhatsApp ≤ 20 символов, строка
  списка ≤ 24, описание строки ≤ 72; быстрый ответ Instagram ≤ 20).
- Язык — русский (кыргызский — Q-08).

### A2. Сценарий

```text
START ─▶ MENU ─┬─ «Букеты дня» ─▶ [POINT?] ─▶ BOUQUETS ─▶ PICKED ─▶ FULFILLMENT
               │                                                    │
               │                       ┌─ Самовывоз ─▶ [POINT?] ────┤
               │                       └─ Доставка ─▶ ZONE ─────────┤
               │                                                    ▼
               │                     DATE ─▶ WINDOW ─▶ [ADDRESS] ─▶ RECIPIENT ─▶ CARD ─▶ SUMMARY
               │                                                                          │
               │                                    «Подтвердить» ─▶ создать pending ─▶ PAY ─▶ WAIT_RECEIPT ─▶ DONE
               ├─ «Собрать на бюджет» ─▶ BUDGET ─▶ WISHES ─▶ handoff (черновик заполнен)
               ├─ «Мой заказ» ─▶ STATUS
               └─ «Позвать менеджера» ─▶ handoff
```

`[POINT?]` — шаг выбора точки, только если активных точек больше одной.

### FR-BT-010 (P0). START и MENU
- Первое входящее в режиме `bot` (любой текст) → приветствие и меню.
- Приветствие по умолчанию: «Здравствуйте! Это {магазин} 🌷 Чем помочь?»
- Меню — кнопки (WhatsApp: список из 4 пунктов, т. к. кнопок максимум 3; Instagram —
  быстрые ответы): «Букеты дня», «Собрать на бюджет», «Мой заказ», «Позвать менеджера».
- В любом состоянии слова «меню», «начать», «старт» возвращают в меню; «менеджер»,
  «оператор», «человек» — handoff.

### FR-BT-011 (P0). Вне рабочего времени
- Если сейчас вне часов всех точек (FR-MP-009): приветствие дополняется «Мы откроемся в
  {часы}. Букеты дня появятся утром, а заказ на завтра можно оформить прямо сейчас».
- «Букеты дня» вне часов показывает вчерашние непроданные (если флорист перенёс их) или
  сообщение «Утром флорист покажет свежие букеты. Хотите собрать букет на бюджет?» с
  кнопками «Собрать на бюджет» / «Позвать менеджера».
- Handoff вне часов: «Менеджер ответит утром, с {часы}. Мы ничего не потеряем».

### FR-BT-020 (P0). Выбор точки
- Если точек несколько, перед букетами: «С какой точки удобнее?» — список точек
  (`short_name` + адрес в описании строки). Точка записывается в разговор и черновик.

### FR-BT-021 (P0). Букеты дня
- Бот отправляет фото доступных букетов точки (статус `available`, сегодня) отдельными
  сообщениями-картинками с подписью «№1 · Пионы ×11 · 4 800 сом», не больше 10, по
  порядку флориста; затем список «Выберите букет» с пунктами №1…№N (до 10 строк
  суммарно во всех секциях WhatsApp). «Собрать на бюджет» и «Позвать менеджера» —
  отдельное сообщение с двумя кнопками, они не увеличивают список до 12 строк.
  Для точек, зон и окон при числе вариантов больше лимита канала используются страницы
  (не более 9 вариантов + «Далее» в WhatsApp), ID выбранного варианта проверяется сервером.
- Если букетов нет: «Сегодня готовые букеты уже разобрали. Соберём на ваш бюджет?» —
  кнопки «Собрать на бюджет», «Позвать менеджера».
- Если букетов больше 10, в P0 показываются первые 10 и возможность позвать менеджера.
  «Показать ещё» — P1; при добавлении пагинации служебный пункт тоже учитывается в лимите.

### FR-BT-022 (P0). Бронь при выборе
- Выбор букета ставит бронь на 30 минут (настройка) на этот разговор (FR-BQ-020).
  Если букет уже забронирован другим или продан: «Этот букет только что выбрали.
  Вот что осталось:» и повтор списка.
- Если клиент не закончил оформление за время брони — бронь снимается, при следующем
  сообщении бот сообщает «Бронь букета истекла» и показывает актуальный список.

### FR-BT-030 (P0). Способ получения, зона, дата, окно
- «Доставка или самовывоз?» — кнопки «Доставка», «Самовывоз».
- Доставка → «Куда доставить?» — список активных зон точки с ценой в описании
  («Центр (до 3 км) · 300 сом»).
- Дата: кнопки «Сегодня», «Завтра», «Другая дата». «Сегодня» доступно, только если у
  точки остались окна сегодня с учётом вместимости и минимального времени на сборку
  (настройка точки, по умолчанию 2 часа до начала окна). «Другая дата» → «Напишите дату,
  например 21.10» → разбор `ДД.ММ` или `ДД.ММ.ГГГГ`; дата в прошлом или дальше 60 дней
  — повтор вопроса.
- Окно: список свободных окон выбранной даты с учётом вместимости
  («09:00–11:00», «11:00–13:00»…). Занятые окна не показываются. Нет окон — «На эту
  дату окна заняты» и выбор другой даты.
- Окно резервируется при создании заказа `pending` (FR-OD-002), не раньше.

### FR-BT-031 (P0). Адрес, получатель, открытка
- Доставка → «Напишите адрес: улица, дом, квартира. Можно отправить геолокацию».
  Принимается текст (не короче 5 символов) или геолокация.
- «Кому вручить? Напишите имя и телефон получателя» — кнопка «Это я»; разбор телефона
  нормализатором (`+996`); без телефона — второй вопрос «Телефон получателя, чтобы
  курьер мог позвонить» (для доставки обязателен, для самовывоза — нет).
- «Добавить открытку?» — кнопки «Да, напишу текст» (+цена позиции «Открытка» из прайса,
  если есть) / «Без открытки».

### FR-BT-032 (P0). Сводка и создание заказа
- Сводка: букет, получение (адрес или точка самовывоза), дата и окно, получатель,
  открытка, доставка, итого; кнопки «Подтвердить», «Изменить», «Позвать менеджера».
  «Изменить» → список шагов для правки.
- «Подтвердить» создаёт заказ `pending` (или `new` без предоплаты) от имени системного
  пользователя «Бот» компании (`created_by`), `source=bot`; уведомление
  `order.bot_created` менеджерам точки.
- Если требуется предоплата и заказ `pending` — QR (FR-PY-010) и переход в
  ожидание чека. При нулевой предоплате заказ сразу `new`: сообщение подтверждения,
  ссылка статуса и `DONE`, без QR на нулевую сумму и требования чека.
- Ошибка создания (окно заняли за секунду до этого) — «Это окно только что заняли.
  Выберите другое:» и список окон.

### FR-BT-033 (P0). Ожидание чека и завершение
- Входящее фото → чек (FR-PY-020), ответ «Спасибо! Проверяем оплату».
- Текст вместо фото — «Пришлите, пожалуйста, скриншот оплаты» (один раз), затем handoff.
- После подтверждения оплаты менеджером — сообщения FR-PY-040; бот возвращается в
  состояние `DONE`, следующее входящее начинает с меню.

### FR-BT-040 (P0). «Собрать на бюджет»
- «На какую сумму собрать?» — кнопки/список «3 000», «5 000», «10 000», «Другая сумма»
  (бюджеты из Настройки → Бот; «Другая сумма» → число от минимальной суммы, по
  умолчанию 1 500).
- «Какие цветы или пожелания? Например: пионы, нежные оттенки, без лилий» — свободный
  текст (до 500 символов).
- Затем бот собирает способ получения, дату, окно, адрес, получателя, открытку теми же
  шагами (FR-BT-030…031) и **передаёт разговор менеджеру** с заполненным черновиком:
  «Спасибо! Флорист подберёт цветы, менеджер пришлёт фото-идею и QR в течение
  {N} минут». Нестандартный заказ подтверждает человек.

### FR-BT-050 (P0). «Мой заказ»
- Бот ищет активные заказы клиента (по идентичностям клиента), показывает до 3:
  «№67 · 18 окт 09:00–11:00 · Собирается» и ссылку статуса. Кнопки «Изменить или
  отменить — позвать менеджера», «Меню».
- Нет активных: «Активных заказов нет. Оформим новый?» — меню.

### FR-BT-060 (P0). Handoff
- По кнопке, по ключевым словам, после двух нераспознанных ответов подряд в одном
  шаге, при ошибке сценария.
- Клиенту: «Подключаю менеджера, он ответит в течение {N} минут» (N из настроек, по
  умолчанию 10; вне часов — FR-BT-011).
- Разговор → `human`, `waiting_since` = сейчас, уведомление `chat.handoff`; черновик
  сохраняет всё, что успел собрать бот (поля `locked`, источник `bot`).

### FR-BT-061 (P0). Нет мест
- Если во всех окнах на ближайшие 3 дня нет мест — бот сообщает «Ближайшие дни
  полностью заняты» и делает handoff. «Режим пикового дня» (очередь, отдельные тексты,
  ограничение заказов в боте) — P2.

### FR-BT-070 (P0). Включение и тестирование бота
- Настройки → Бот: «Бот включён» (по умолчанию включён после подключения канала),
  тексты, бюджеты, время ответа менеджера для текста handoff, срок брони, минимальное
  время на сборку, быстрые ответы.
- «Проверить бота» — запуск сценария в предпросмотре внутри CRM (без отправки в
  WhatsApp): чат-симулятор с кнопками.
- Выключенный бот: новые разговоры сразу `human`, автоответ «Здравствуйте! Менеджер
  ответит в течение {N} минут».

### FR-BT-080 (P1). Напоминание при ожидании человека
- Пока разговор `human`, бот не отвечает. Если менеджер не ответил за 30 минут в
  рабочие часы, бот один раз пишет «Менеджер скоро ответит. Хотите пока посмотреть
  букеты дня?» с кнопкой «Букеты дня» (P1, можно выключить).

### FR-BT-090 (P0). Согласие на напоминания
- После подтверждения оплаты бот один раз спрашивает: «Можно напоминать вам о важных
  датах, например о дне рождения мамы?» — кнопки «Да, напоминайте» / «Нет, спасибо».
- «Да» ставит согласие клиента с записью (источник `bot`, канал, время, текст вопроса);
  «Нет» — запись отказа. Повторно не спрашивает 180 дней.

## Часть B. Букеты дня

### B1. Цель

Флорист в начале смены фотографирует готовые букеты и ставит цену. Бот и менеджеры
предлагают только их. Каждый букет существует в одном экземпляре: после продажи
(через бота, менеджера или в магазине) он исчезает из предложения.

### B2. Модель (`catalog.BouquetOfDay`, новая)

| Поле | Описание |
| --- | --- |
| `id` | UUID |
| `business`, `point` | |
| `number` | Номер дня на точке (1, 2, 3…), сбрасывается каждый день |
| `title` | Короткое описание: «Пионы ×11» (по умолчанию «Букет дня №N») |
| `price` | Decimal |
| `photo_key` | Фото в закрытом хранилище |
| `composition` | Необязательно: состав/теги («пионы, эустома») |
| `status` | `available` \| `reserved` \| `sold` \| `withdrawn` \| `expired` |
| `reserved_until`, `reserved_conversation`, `reserved_order` | Бронь |
| `order` | Заказ, куда продан |
| `sold_offline_at` | «Продан в магазине» |
| `shift_date` | Дата смены |
| `created_by`, `created_at`, `updated_at`, `version` | |

### FR-BQ-001 (P0). Экран «Букеты дня»
- Новый пункт меню «Букеты дня» для владельца, менеджера и флориста (у флориста —
  своя точка). Сетка карточек: фото, №, название, цена, статус («в наличии»,
  «бронь до 10:42», «продан №67», «продан в магазине»).
- Кнопка «Добавить букет»: камера телефона или файл, затем цена (быстрые суммы 2 000 /
  3 500 / 5 000 / своя) и название (необязательно). Можно загрузить несколько фото
  подряд.
- Порядок карточек меняется перетаскиванием; этот порядок использует бот.
- Подсказка вверху: «Сфотографируйте готовые букеты до 10:00 — бот будет предлагать
  клиентам только их».

### FR-BQ-002 (P0). Загрузка фото
- Те же проверки и обработка, что у фото заказов (размер до 10 МБ, PNG/JPEG/WebP/HEIC с
  конвертацией в JPEG, очистка метаданных, ограничение разрешения).
- При отправке в WhatsApp фото загружается в медиа Meta один раз и переиспользуется в
  течение срока жизни ID медиа (FR-CH-021).

### FR-BQ-010 (P0). Изменение и снятие
- Цену и название можно менять, пока букет `available`; изменение не меняет уже
  созданные заказы.
- «Снять» (`withdrawn`) — букет испортился; доступно для `available` или брони
  разговора без заказа, с уведомлением разговора. Букет, связанный с заказом,
  нельзя снять независимо от заказа: менеджер сначала решает замену или отмену.

### FR-BQ-012 (P0). «Продан в магазине»
- Одно касание на карточке (с подтверждением) → `sold`, `sold_offline_at`,
  только для `available` или брони разговора без заказа. Проверка и продажа —
  под той же блокировкой, что бронь/создание/подтверждение заказа. Бронь заказа
  и уже проданный в заказ букет повторно продать нельзя (409).
  Если была только бронь разговора — клиенту сообщение об офлайн-продаже
  по правилам канала; бот перестаёт предлагать букет.
- Создавать заказ для офлайн-продажи не нужно (P2: быстрый «чек на кассе»).

### FR-BQ-020 (P0). Бронь
- Бронь ставится сценарием в одной транзакции с блокировкой строки букета: второй
  клиент не может забронировать тот же букет (тест на одновременность).
- Бронь из бота живёт `reserved_until` (30 минут по умолчанию); бронь заказа `pending` —
  до подтверждения оплаты или отмены заказа (FR-OD-004).
- Задача раз в минуту снимает только истёкшие брони разговоров без заказа.
  Бронь с `reserved_order` освобождается только при отмене заказа по FR-OD-004;
  таймер не обходит частичную оплату/чек на проверке.
- Менеджер снимает бронь разговора вручную; для брони заказа требуется действие
  над заказом. Во всех переходах проверяются текущие статус и владелец брони.

### FR-BQ-021 (P0). Продажа
- Подтверждение заказа (`pending → new`) или создание заказа сразу `new` с букетом →
  букет `sold`, `order` заполнен.
- Отмена заказа до `work` возвращает букет в `available` (если он не `expired`);
  после `work` — нет (букет уже в работе). Возврат до `work` допустим только
  в текущей смене; после закрытия — `expired` по FR-BQ-030.

### FR-BQ-030 (P0). Конец дня
- В час закрытия точки букеты `available` без заказа получают `expired`.
  Истёкшая бронь разговора тоже становится `expired`, если смена уже закончилась;
  освобождение после отмены заказа не возвращает старый букет в продажу автоматически.
- Букеты с бронью заказа или уже проданные не истекают и не переносятся массовым
  действием: решение о замене/отмене принимает менеджер.
- Для свободных букетов флорист до закрытия отмечает «Перенести на завтра».
  Перенос применяется в конце смены (сейчас букет остаётся доступен); дата смены
  и новый номер меняются атомарно. Конкурентная продажа/бронь отменяет перенос.

### FR-BQ-031 (P1). Напоминание флористу
- Если к 10:00 (или через 1 час после открытия точки) у точки нет ни одного
  `available` букета — push `bouquets.missing` флористам точки.

### FR-BQ-040 (P0). Менеджер в чате
- Кнопка «Букеты дня» в поле ввода чата показывает доступные букеты точки разговора;
  выбор отправляет фото с подписью клиенту и ставит бронь на этот разговор.

## Тесты

- Автомат бота: таблица переходов для каждого состояния, каждое ключевое слово,
  нераспознанный ввод (1 и 2 раза), версия сценария, вне часов, одна и несколько точек.
- Сквозной сценарий через двойник канала: меню → букет → доставка → зона → завтра →
  окно → адрес → получатель → без открытки → подтвердить → `pending` → QR → фото чека →
  подтверждение менеджером → `new` → сообщения клиенту.
- Одновременность: два разговора выбирают один букет — бронь получает один; офлайн-
  продажа во время брони; истечение брони.
- Ограничения длины и числа кнопок/строк: 10 букетов + два действия, >10 зон/окон.
- Самовывоз с 0 % предоплаты → `new` без ожидания чека.
- Букет с `pending`, оплатой или чеком нельзя продать офлайн, освободить таймером
  разговора либо перенести в следующую смену.
- Бюджет: handoff с заполненным черновиком; минимальная сумма.
