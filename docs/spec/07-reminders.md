# 07. Напоминания: экран «Кому написать сегодня» и сценарии

Решения: D-12, D-13, D-24. Макеты: `design-reminders/v2/png/1-list.png` (главный экран),
`design-reminders/v2/png/4-settings-scenarios.png` (настройки). Из невыбранного варианта 2
берутся две вещи: подсказка «в прошлом году на этот повод» и автоотметка «Написали».

## 1. Текущее состояние

- `ReminderSettings` (на компанию): `enabled`, `offsets` (по умолчанию 14, 7, 3, 1),
  `inactive_days` (90), `start_hour`/`end_hour` (9–20), `templates` по интервалам,
  `custom_templates`, `template`, `inactive_template`.
- `ReminderRecord`: `key` (уникален: `date:<event>:<год>:<интервал>` или
  `inactive:<клиент>:<последний заказ>`), `event`, `person`, `due_date`, `state`
  (`wait`, `sent`, `skipped`, `answered`, `ordered`), `message`, `actor`, `acted_at`.
- Планировщик Celery каждые 15 минут восстанавливает очередь; сообщения не отправляет.
  Отправка — ссылка WhatsApp с текстом и ручное подтверждение.
- Экран: текст с объяснением, три счётчика, фильтры видов и выпадающий фильтр
  состояния, кнопка «Сформировать очередь на сегодня», «Шаблоны» уводит в Настройки,
  «Правила» — форма на месте со строкой «14, 7, 3, 1». Это и путает.

## 2. Цель

Утром менеджер открывает один экран, видит, кому написать сегодня, и проходит
очередь за ~10 минут. Все настройки (когда и что писать) — в одном отдельном экране
сценариев. Отправка остаётся ручной и бесплатной (D-12).

## 3. Модель данных

### 3.1. Сценарий (`reminders.ReminderScenario`, новая)

| Поле | Описание |
| --- | --- |
| `id` | UUID |
| `business` | |
| `kind` | `before_event` \| `after_last_order` \| `after_delivery` \| `holiday` |
| `name` | «День рождения», «Годовщина и свадьба», «Другие важные даты», «Давно не заказывали», «Спасибо после доставки», «8 Марта» |
| `enabled` | |
| `event_labels` | Для `before_event`: какие метки важных дат входят (например `["День рождения"]`; пусто = «все остальные») |
| `holiday_month`, `holiday_day`, `audience` | Для `holiday`: дата и аудитория (`consented_all`, `ordered_last_year`) |
| `daily_cap` | Для `holiday`: не больше N в день (по умолчанию 40), остальные — на следующий день окна |
| `sort` | |
| `version` | |

### 3.2. Шаг сценария (`reminders.ReminderStep`, новая)

| Поле | Описание |
| --- | --- |
| `scenario` | FK |
| `offset_days` | Для `before_event`/`holiday` — за сколько дней до даты; для `after_*` — через сколько дней после |
| `template` | Текст с подстановками |
| `include_orders_link` | Добавлять ли строку со ссылкой на номер для заказов (D-24), по умолчанию да, если номер подключён |
| `sort` | |

### 3.3. Общие правила (остаются в `ReminderSettings`)

`enabled`, `start_hour`/`end_hour` (тихие часы), `consent_only` (всегда `true` в P0,
переключатель только для показа), `pause_on_complaint` (`true`), `min_days_between`
(не чаще одного напоминания клиенту в N дней, по умолчанию 7).

### 3.4. Изменения записи напоминания (`ReminderRecord`)

| Поле | Описание |
| --- | --- |
| `scenario`, `step` | FK, ссылки на сценарий и шаг |
| `point` | Точка (FR-MP, раздел 4.4) |
| `last_year_hint` | JSON: прошлый заказ на этот повод (номер, дата, состав, сумма) |
| `sent_via` | `wa_link` (ручная ссылка) — на будущее `api` |
| `order` | FK на заказ, если «Заказали» |
| `snoozed_until` | «Позже» |

Ключ уникальности сохраняет формат, чтобы повторы планировщика не плодили дубли.

### 3.5. Миграция

Из текущих `ReminderSettings` создаются сценарии:
- «День рождения» и «Годовщина и свадьба», «Другие важные даты» (`before_event`) с шагами из `offsets` и
  текстами из `templates` по интервалам (если текста нет — текст по умолчанию);
- «Давно не заказывали» (`after_last_order`, `inactive_days`, `inactive_template`);
- «Спасибо после доставки» и «8 Марта» — выключены.
Существующие `ReminderRecord` получают ссылку на сценарий по ключу; состояния не меняются.

## 4. Главный экран (вариант 1)

### FR-RM-001 (P0). Шапка и прогресс
- Заголовок «Кому написать сегодня», подпись «Суббота, 17 октября · список собирается
  сам каждое утро», справа кнопка «Настройки напоминаний».
- Полоса прогресса: «6 из 28 отправлено», зелёная полоса, факты «Ждём ответа 6 ·
  Ответили 3 · Заказали за неделю 4 · 18 200 сом», справа «осталось ≈ 10 минут»
  (оценка: 25 секунд на одно напоминание).
- Убрать: объясняющий текст про 15 минут, кнопку «Сформировать очередь на сегодня»,
  выпадающий фильтр состояния. Обновление очереди — только в фоне (и скрытое действие
  «Обновить список» в меню ⋯ для владельца).

### FR-RM-002 (P0). Вкладки и фильтр
- Вкладки со счётчиками: «Написать», «Ждём ответа», «Ответили», «Заказали», «Пропущено».
- Справа «Все поводы ▾»: фильтр по сценариям.
- Менеджер видит очередь своих точек; владелец — выбранной точки или «Все точки».

### FR-RM-003 (P0). Группы по срочности
Во вкладке «Написать» строки сгруппированы (заголовки с числом):
«Сегодня событие», «Завтра» (красный), «Через 3 дня», «Через неделю», «Через 2 недели»,
«Давно не заказывали», «Праздник: 8 Марта». Внутри — по дате события, затем по имени.

### FR-RM-004 (P0). Строка напоминания
- Аватар, имя клиента, чип даты события с цветом срочности, повод и получатель
  («День рождения мамы · Айжан»), первая строка текста сообщения (обрезка), колонка
  «Прошлый заказ: 6 350 сом · 12 сен», действия **«WhatsApp»**, «Позже», меню ⋯.
- **Подсказка «год назад»** (из варианта 2): если год назад (±10 дней) у клиента был
  заказ на этот же повод или этому же получателю — под текстом чип «Год назад:
  «Нежность», 3 500 сом». Подстановка `{прошлый_букет}` в тексте берёт это название.
- Меню ⋯: «Изменить текст» (правка только этого сообщения), «Открыть карточку»,
  «Пропустить в этом году» (подавляет оставшиеся шаги события в этом году), «Не
  напоминать клиенту» (снимает согласие с записью источника).

### FR-RM-005 (P0). Отправка
- «WhatsApp» открывает ссылку `https://wa.me/<телефон клиента>?text=<текст>` в новой
  вкладке/приложении. Сообщение отправляет сотрудник из своего WhatsApp (обычно —
  основной номер магазина на рабочем телефоне).
- **Автоотметка «Написали»** (из варианта 2): нажатие сразу переводит запись в `sent`
  (оптимистично) и показывает внизу «Отмечено «Написали» · Отменить» на 10 секунд.
- Перед открытием сервер ещё раз проверяет согласие, жалобы, тихие часы и частоту
  (как сейчас); если нельзя — ссылка не открывается, причина в строке.
- В тихие часы кнопка неактивна с подсказкой «Можно писать с 9:00».

### FR-RM-006 (P0). Результат
- В «Ждём ответа» у строки — «Отправлено в 09:42 · ждём ответа» и кнопки «Ответил(а)»,
  «Заказал(а)».
- «Заказал(а)» предлагает выбрать заказ клиента, созданный после отправки, или
  «Создать заказ» (форма заказа с получателем и поводом из напоминания). Запись
  связывается с заказом (`order`), выручка попадает в «Заказали за неделю».
- **FR-RM-007 (P1). Авто-«Заказали».** Если клиент оформил заказ (любым способом) в
  течение 7 дней после отправки, запись автоматически получает `ordered` и связь с
  заказом.
- «Позже» переносит запись на завтра (`snoozed_until`) с подписью в строке.

### FR-RM-008 (P0). Ссылка на номер для заказов (D-24)
- Ответы на ручные напоминания приходят на основной номер, CRM их не видит. Чтобы
  заказ пришёл в отслеживаемый канал, шаг сценария может добавлять в конец текста строку
  «Оформить заказ: wa.me/<номер для заказов>» (`include_orders_link`).
- Это единственная разрешённая ссылка в тексте напоминаний (проверка FR-RM-022).

### FR-RM-009 (P0). Мобильный вид
- На ширине 390 строки становятся карточками: имя и дата, повод, текст в 2 строки,
  кнопка «WhatsApp» на всю ширину, «Позже» и ⋯ рядом. Без горизонтальной прокрутки.

## 5. Экран настроек напоминаний (по макету)

### FR-RM-020 (P0). Структура
- Путь: «Настройки напоминаний» с главного экрана и Настройки → «Напоминания».
  Ссылка «← К напоминаниям».
- Слева: список «Сценарии» с подписью «Сценарий = когда написать + что написать»,
  группы «Перед важной датой», «После покупки», «Праздники»; у каждого — значок,
  название, краткое описание шагов («за 14 · 3 · 1 день»), переключатель; кнопка «Новый».
  Внизу — «Общие правила»: «Писать только 09:00–20:00», «Только с согласием клиента»,
  «Пауза при открытой жалобе», «Не чаще одного в 7 дней».
- В центре — редактор выбранного сценария, справа — «Так увидит клиент».
- Вкладка «Шаблоны» в Настройках удаляется; «Свои шаблоны» переезжают в «Быстрые
  ответы» ([04](04-chats-and-crm.md), FR-CR-008) или становятся шагами сценариев (по
  выбору при миграции — переносим в быстрые ответы).

### FR-RM-021 (P0). Редактор сценария
- Шапка: значок, название, «Включён · 22 клиента в октябре» (оценка по датам месяца),
  кнопки «Отправить себе тест» и «Сохранить».
- **Когда:** предложение-конструктор «Напомнить за [14] [3] [1] [+] дн. до события
  [День рождения ▾]» (для `after_last_order` — «Написать через [90] дней после последнего
  заказа»; для `holiday` — «Написать за [5] дн. до [8 марта]»). Числа — от 0 до 60
  (для «давно не заказывали» — 30…365), без повторов.
- **Что написать:** вкладки по шагам («За 14 дней», «За 3 дня», «За 1 день»), поле текста
  с подстановками, показанными как чипы, строка «Вставить: Имя · Получатель · Повод ·
  Дата · Прошлый букет · Магазин · Ссылка на заказ».
- Поддерживаемые подстановки (фиксированный список, как сейчас):
  `{имя}`, `{получатель}`, `{повод}`, `{дата}`, `{прошлый_букет}`, `{магазин}`,
  `{ссылка_на_заказ}`. Неизвестная подстановка — ошибка сохранения.

### FR-RM-022 (P0). Проверка текста
Правила без ИИ, показываются под полем как чипы (зелёная галочка или жёлтое предупреждение):
- есть `{имя}` — «Обращение по имени»;
- для «перед датой» есть `{повод}` или `{дата}` — «Повод и дата»;
- текст заканчивается вопросом — «Вопрос в конце»;
- нет ссылок, кроме `{ссылка_на_заказ}`, и нет слов КАПСОМ длиннее 3 букв (кроме названия
  магазина) — «Без ссылок и КАПСА»;
- длина: до 250 символов — норма, 251–500 — «короче читают чаще», больше 500 — ошибка.
- Предупреждения не мешают сохранить; ошибки — мешают.

### FR-RM-023 (P1). Помощник текста (ИИ)
- Кнопки «Сделать теплее», «Короче, до 150 символов», «Упомянуть букеты дня», «Три новых
  варианта». Результат показывается как варианты под полем; применить вариант — по
  кнопке, сохранить — отдельно. Подстановки в вариантах сохраняются.
- Тот же порт ИИ, что в [05](05-order-draft-and-payments.md), отдельный метод
  `rewrite_reminder`; в ИИ уходит только текст шаблона и название сценария, без данных клиентов.

### FR-RM-024 (P0). Предпросмотр и тест
- Справа — сообщение в стиле WhatsApp с подстановками реального клиента (выбор
  «пример ▾» из ближайших клиентов сценария; если таких нет — вымышленный пример).
- «Отправить себе тест» открывает `wa.me/<телефон текущего сотрудника>` с текстом.
- Подпись: «Сообщение отправляет сотрудник из своего WhatsApp — CRM только готовит
  текст и открывает чат».

### FR-RM-025 (P0). Правила попадания в очередь
- Клиент попадает в очередь шага, если: сценарий и шаг включены; есть согласие;
  нет открытой жалобы; не «Не клиент»; есть телефон; не отправляли этому клиенту
  напоминание `min_days_between` дней; для «давно не заказывали» — нет активных заказов.
- Если в один день у клиента совпали несколько шагов — остаётся ближайшее событие,
  остальные помечаются `skipped` с причиной «другое напоминание».
- Праздничный сценарий: аудитория по настройке, не больше `daily_cap` в день, начало
  за N дней до даты; остаток переносится на следующий день до даты праздника.

### FR-RM-026 (P1). Сценарий «Спасибо после доставки»
- Через N дней (по умолчанию 1) после вручения — напоминание поблагодарить и попросить
  отзыв (ссылка — `{ссылка_на_заказ}` не используется, в тексте предлагается ответить
  оценкой). Выключен по умолчанию, чтобы не дублировать автосообщение FR-PY-040.

## 6. API

| Метод и путь (`/api/v1/businesses/{id}/…`) | Описание |
| --- | --- |
| `GET reminders/?tab=write\|waiting\|answered\|ordered\|skipped&scenario=&point=` | Очередь с группами и статистикой полосы |
| `POST reminders/{rid}/open/` | Проверить и вернуть ссылку `wa.me`, отметить `sent` (идемпотентно) |
| `POST reminders/{rid}/undo-sent/` | Отмена автоотметки в течение 10 секунд |
| `POST reminders/{rid}/action/` | `answered`, `ordered` (+`order_id`), `snooze`, `skip_year`, `opt_out` |
| `PATCH reminders/{rid}/` | Изменить текст этого сообщения |
| `GET/POST reminder-scenarios/`, `GET/PATCH/DELETE reminder-scenarios/{sid}/` | Сценарии и шаги |
| `POST reminder-scenarios/preview/` | Текст с подстановками для выбранного клиента |
| `POST reminder-scenarios/rewrite/` | Помощник ИИ (P1) |
| `GET/PATCH reminder-rules/` | Общие правила (существующий эндпоинт, сокращённый) |

## 7. Тесты

- Миграция настроек в сценарии без изменения существующих записей и ключей.
- Правила попадания: согласие, жалоба, частота, совпадение шагов, «давно не заказывали»
  с активным заказом, праздник с лимитом и переносом.
- Автоотметка и отмена в течение 10 секунд; повторное открытие ссылки не меняет время отправки.
- Подсказка «год назад»: окно ±10 дней, получатель или повод, пустая история.
- Проверка текста: каждое правило, неизвестная подстановка, длина.
- Playwright: пройти 3 напоминания (WhatsApp → Ответила → Заказала с созданием заказа),
  ширины 1440 и 390.
