# 12. Чаты к понедельнику — пилот на номере WhatsApp для заказов

Версия 1.0 · суббота, 17 октября 2026. **Цель: к понедельнику, 19 октября, всё
готово к подключению номера для заказов у Meta.** В понедельник остаётся только
пройти [инструкцию подключения](../runbooks/meta-whatsapp-manual-connect.md) и
проверить реальным сообщением.

[02](02-notifications.md)) с явными упрощениями для пилота. Где здесь не сказано
иначе, действуют правила основного ТЗ (особенно FR-CH-010…013 и FR-CH-020 —
приём вебхуков и исходящая очередь).

## 2. Решения для пилота

- **D-25. Ручное подключение.** Приложение Meta создаётся **в бизнес-аккаунте
  магазина** (D-02), номер для заказов добавляется туда же, доступ даёт постоянный
  токен системного пользователя этого бизнес-аккаунта. Tapme хранит на канале токен
  и App Secret (зашифрованно) и показывает адрес вебхука. Встроенная регистрация
  через Tapme (FR-CH-001) — после статуса технического провайдера (S-01).
  Почему: проверка приложения Tapme у Meta за два дня невозможна, а приложение
  магазина работает с собственным номером магазина без неё. Это проверяется в
  понедельник первым делом (если Meta потребует проверку — план Б в инструкции).
- **D-26. Отдельный адрес вебхука на канал.** У каждого канала свой адрес
  `/api/v1/webhooks/meta/whatsapp/<webhook_key>/` и свой verify token; подпись
  проверяется App Secret этого канала. Общий `META_APP_SECRET` для ручного режима не
  используется.
- **D-27. Опрос вместо потока событий.** Открытый разговор обновляется раз в 3
  секунды, список и счётчики — раз в 10 секунд. В фоновой вкладке браузер может
  замедлять опрос до раза в минуту — это известное ограничение пилота до push и SSE.
- **D-28. Только режим «человек».** Бота нет; на первое сообщение нового разговора
  уходит автоответ.
- **D-29. Без шаблонов Meta.** После 24 часов молчания клиента отправка из CRM
  недоступна (окно закрыто). Шаблоны подаются на одобрение в понедельник и
  подключаются следующим этапом (T-13).

## 4. Требования

### Канал и подключение

**CM-CH-01. Ручное подключение (владелец).** Настройки → новая вкладка «Каналы»
(добавляется к существующим «Сотрудники · Окна доставки · Шаблоны · Прайс · Магазин»).
Форма: Phone number ID, WhatsApp Business Account ID, постоянный токен, App Secret.
- «Сохранить и проверить»: сервер шифрует секреты, запрашивает у Graph API данные
  номера (`display_phone_number`, `verified_name`, `quality_rating`) и показывает
  «Токен работает · номер +996… · «имя»» или понятную ошибку (неверный токен, нет
  доступа к номеру, неверный ID).
- После сохранения показываются **Callback URL** и **Verify token** с кнопками
  «Копировать» и подсказкой «Вставьте в Meta → WhatsApp → Конфигурация → Вебхук» и
  списком полей подписки: `messages`, `message_template_status_update`,
  `phone_number_quality_update`, `account_update`.
- Секреты после сохранения не показываются (маска), можно заменить новыми.
- Менеджер видит вкладку без формы и секретов (только статус). Флорист и курьер — нет доступа.

**CM-CH-02. Регистрация номера.** Кнопка «Зарегистрировать номер (PIN)» — ввод
шестизначного PIN двухэтапной проверки; сервер вызывает регистрацию номера в Cloud
API. PIN не сохраняется. Ошибка Meta показывается текстом.

**CM-CH-03. Проверка вебхука.** `GET` по адресу канала с `hub.mode=subscribe` и
совпадающим `hub.verify_token` возвращает `hub.challenge` и ставит
`webhook_verified_at`; иначе 403. В карточке канала отметка «Вебхук подтверждён Meta».

**CM-CH-04. Подписка приложения на аккаунт.** Кнопка «Подписать» вызывает подписку
приложения на сообщения аккаунта WhatsApp Business и проверяет её; отметка
«Приложение подписано на сообщения этого аккаунта».

**CM-CH-05. Чек-лист состояния** (по макету): токен работает; номер зарегистрирован;
вебхук подтверждён; приложение подписано; тестовое сообщение получено (первое
входящее). Статус канала: «Ждём вебхук» → «Подключён» (все пункты выполнены) →
«Связь работает · последнее сообщение HH:MM».

**CM-CH-06. Отключение.** «Отключить» с подтверждением: секреты удаляются,
статус `disconnected`, вебхуки канала отвечают 404, переписка остаётся для чтения.

**CM-CH-07. QR для оплаты** (карточка в «Каналах»): загрузка картинки QR (PNG/JPEG/WebP
до 5 МБ, та же обработка, что фото заказов), подпись («MBank · Бермет У.»), текст
сообщения с `{номер}` и `{сумма}`.

**CM-CH-08. Автоответ** (карточка в «Каналах»): переключатель, текст «в рабочие часы»,
текст «после работы», рабочие часы (с–до, по умолчанию 09:00–20:00, часовой пояс
компании). По умолчанию включён с текстами из макета.

**CM-CH-09. Основной номер** (карточка): номер из настроек магазина, «Не подключается»,
текст приветствия со ссылкой `wa.me/<номер для заказов>` и «Скопировать».

### Приём сообщений

**CM-IN-01. Вебхук.** `POST /api/v1/webhooks/meta/whatsapp/<webhook_key>/` — без сессии и
CSRF. Подпись `X-Hub-Signature-256` проверяется App Secret канала **до** разбора JSON и
записи (правила FR-CH-010). Тело ≤ 1 МБ. Ответ 200 после записи `WebhookEvent`;
обработка — задача Celery после commit; сторож раз в минуту подбирает
необработанные записи. Неизвестный `webhook_key` или отключённый канал → 404.
`phone_number_id` в теле должен совпадать с каналом, иначе событие `ignored`.

**CM-IN-02. Входящие сообщения.** Поддерживаются `text`, `image`, `audio` (включая
голосовые), `document`, `location`, `video`, `sticker`, `reaction`, `contacts`;
неизвестный тип — строка «Клиент отправил сообщение, которое пока не поддерживается».
Ответ клиента на конкретное сообщение (`context`) показывается цитатой.
Идемпотентность по `wamid`, порядок по `timestamp` (FR-CH-012).

**CM-IN-03. Клиент и разговор.**
- Номер клиента нормализуется в `+<wa_id>` и ищется среди `phone` и `additional_phones`
  клиентов компании.
- Одно совпадение — разговор привязан к клиенту.
- Нет совпадений — создаётся клиент: имя = имя профиля WhatsApp или номер,
  `origin=whatsapp`, без согласия на напоминания; через существующий сценарий создания
  клиента (счётчик кодов, уникальность).
- Несколько совпадений (номер в дополнительных телефонах разных клиентов) — клиент
  **не выбирается автоматически**: разговор без клиента, в правой панели «Этот номер
  есть у нескольких клиентов — выберите» (только имена), история заказов не
  показывается до выбора (правило ревью, Q-22).
- Всё — в одной транзакции с записью сообщения.

**CM-IN-04. Медиа.** Скачивание по ID медиа сразу после записи (фоновая задача).
Изображения — обработка как фото заказов; аудио, видео, документы — как есть до 16 МБ,
больше — пометка «Файл слишком большой». Чтение — только через API с сессией
(владелец, менеджер). Ключи хранилища `messages/<business>/<conversation>/…`.

**CM-IN-05. Статусы.** `sent → delivered → read`, `failed` с кодом и текстом;
статус не понижается; статус для неизвестного сообщения повторяется до 5 минут.

**CM-IN-06. Автоответ.** Если автоответ включён и это первое входящее разговора или
первое после 24 часов тишины — в ту же минуту уходит один автоответ (текст по
рабочим часам). Не больше одного автоответа на разговор за 12 часов. В ленте он
подписан «Автоответ».

### Отправка

**CM-OUT-01. Текст** из поля ввода (Enter — отправить, Shift+Enter — новая строка),
до 4096 символов. Сообщение сразу появляется в ленте со статусом «отправляется».
Очередь и состояния — строго по FR-CH-020 (`queued → sending → sent`, `unknown` без
слепого повтора, понятные ошибки).

**CM-OUT-02. Фото и документы** с компьютера или камеры телефона (JPEG/PNG/WebP до
5 МБ, PDF до 16 МБ), с необязательной подписью. Загрузка в медиа Meta, затем отправка.

**CM-OUT-03. «Отправить QR».** Диалог: сумма (по умолчанию — неоплаченный остаток
последнего незавершённого заказа клиента, если есть; иначе пусто), номер заказа
(необязательно). Отправляются картинка QR и текст из CM-CH-07 с подстановками. Если
QR не загружен — «Сначала загрузите QR в Настройки → Каналы» (владельцу — ссылка).

**CM-OUT-04. Окно 24 часа.** Если с последнего входящего прошло ≥ 24 часов — поле ввода
заменяется сообщением «Окно закрыто — клиент молчит больше 24 часов. Шаблоны Meta
подключим следующим этапом». За 4 часа до закрытия — «Окно открыто ещё N ч M мин»,
иначе «Окно открыто». Сервер повторно проверяет окно перед отправкой.

**CM-OUT-05. Прочтение.** Открытие разговора сотрудником отправляет отметку прочтения
последнего входящего (одна на открытие).

**CM-OUT-06. Быстрые ответы.** Владелец и менеджер создают, правят, удаляют быстрые
ответы (диалог из кнопки «Быстрые ответы» → «Управлять»). Выбор вставляет текст с
подстановками `{имя}`, `{магазин}` в поле для правки, не отправляя.

### Интерфейс «Чаты» (по макету `5-chats-monday`)

**CM-UI-01. Маршрут и меню.** Новый вид `view=chats` с параметром `conversation`.
Пункт меню «Чаты» после «Заказов», видят владелец и менеджер; счётчик — разговоры с
`waiting_since` (не число сообщений).

**CM-UI-02. Список.** Шапка «Чаты · WhatsApp · номер для заказов», чипы «Все N»,
«Ждут ответа N», «Мои N»; строки по макету; сортировка: ждущие ответа по времени
ожидания, затем по последнему сообщению; поиск по имени и номеру; подгрузка по 50.

**CM-UI-03. Разговор.** Шапка: аватар, имя или номер, «новый клиент» (если клиент
создан этим разговором и имя не подтверждено), «WhatsApp · номер заказов · пишет с
HH:MM», ответственный (выбор из владельца и менеджеров). Лента по макету, подгрузка
истории вверх по 50, кнопка «Новые сообщения ↓» при прокрутке вверх.

**CM-UI-04. Поле ввода** по макету: «Фото», «Отправить QR», «Быстрые ответы»,
индикатор окна, поле «Ответить в WhatsApp…», кнопка отправки.

**CM-UI-05. Правая панель** по макету:
- новый клиент — «Клиент создан автоматически», «Имя в WhatsApp: «…»», поле «Как зовут
  клиента?» (сохранение меняет имя клиента и убирает метку «новый клиент»);
- известный клиент — имя, телефон, число заказов и сумма, ближайшая важная дата,
  «Открыть карточку»;
- неоднозначный номер — выбор клиента (CM-IN-03);
- блок «Заказ» и кнопки «Создать заказ» (открывает существующую форму заказа с
  выбранным клиентом и источником «WhatsApp») и «Отправить QR для оплаты»;
- «Заказы клиента» — последние 5 с номером, датой и статусом.

**CM-UI-06. Ответственный.** Первый сотрудник, отправивший сообщение (или выбравший
себя), становится ответственным разговора и клиента (FR-CR-030). Дальше — только
вручную. Системная строка в ленте при назначении.

**CM-UI-07. Ширина 390.** На телефоне — список и разговор отдельными экранами
(назад к списку), правая панель — кнопкой «Клиент» в шапке. Без горизонтальной прокрутки.

**CM-UI-08. Пустые состояния.** Нет канала: «Подключите номер для заказов в Настройки →
Каналы» (владельцу — кнопка). Канал есть, разговоров нет: «Напишите со своего
телефона на +996… — сообщение появится здесь».

### Уведомления

**CM-NT-01. Звук и всплывающее уведомление.** Когда в доступных разговорах появилось
новое входящее (определяется опросом), CRM проигрывает звук и показывает уведомление
«Новое сообщение от <имя/номер>» со ссылкой. Не чаще одного звука в 3 секунды.
До первого действия пользователя на странице — кнопка «Включить звук» в шапке.

**CM-NT-02. Заголовок вкладки.** При непрочитанных — «(N) Tapme», мигание раз в секунду,
пока вкладка не активна.

**CM-NT-03. Кому.** Звук и уведомление — ответственному; если ответственного нет —
всем владельцам и менеджерам, у кого открыта CRM.

### Клиенты

**CM-CL-01.** В списке «Клиенты» — метка «из чата» у `origin=whatsapp` и фильтр
«Канал: WhatsApp».
**CM-CL-02.** В карточке клиента — кнопка «Чат», если у клиента есть разговор.
**CM-CL-03.** Флорист и курьер по-прежнему не видят клиентов и переписку.

### Безопасность

**CM-SE-01.** Изоляция: разговоры, сообщения, медиа, быстрые ответы, канал — только своей
компании; тесты с подстановкой чужих ID → 404.
**CM-SE-02.** Роли: все эндпоинты чатов и каналов — владелец и менеджер; форма
подключения и секреты — только владелец; флорист/курьер → 403.
**CM-SE-03.** Секреты зашифрованы, не возвращаются API, не пишутся в логи.
**CM-SE-04.** Вебхук: подпись канала, лимит тела, ограничение частоты (300/мин на IP).

### Разработка без Meta

**CM-DEV-01. Режим `TAPME_META_MODE=fake`.** Исходящие уходят в двойник: возвращает
внешний ID, через 1 и 2 секунды присылает статусы `delivered` и `read` (через тот же
путь обработки статусов). Регистрация, проверка токена и подписка всегда успешны.
По умолчанию в разработке — `fake`, на сервере — `live`.

**CM-DEV-02. Симулятор входящих.** Команда
`manage.py simulate_whatsapp --business <id> --from +996700481209 --name Aidana --text "…"`
(и `--image путь`, `--audio путь`, `--location 42.87,74.59`) собирает тело как у Meta,
подписывает App Secret канала и отправляет на адрес вебхука канала — проверяется весь
настоящий путь. В режиме `fake` и `DEBUG` — то же из интерфейса: «Каналы → Симулятор»
(только владелец).

**CM-DEV-03. Фикстуры.** `tests/fixtures/meta/whatsapp/*.json` — входящие всех типов,
статусы, пример с `context`, пример с двумя сообщениями в одном теле.

### Сервер

**CM-OPS-01.** Рабочий сервер по `compose.production.yaml` с доменом и HTTPS (Caddy),

**CM-OPS-02.** Переменные: `TAPME_SECRETS_KEY` (сгенерировать), `TAPME_META_MODE=live`,

**CM-OPS-03.** Страницы `/privacy` и `/terms` на домене (статичные, текст — черновик до

**CM-OPS-04.** Работают `worker` и `beat`; задачи сторожа (вебхуки, исходящие) — раз в

## 8. Проверка в воскресенье вечером (режим `fake`, на сервере)

1. Владелец входит, Настройки → Каналы: вводит тестовые ID, токен и секрет →
   «Токен работает» (двойник), появляются Callback URL и Verify token.
2. `curl` на адрес вебхука с `hub.mode=subscribe`, верным и неверным токеном → challenge / 403.
3. Симулятор: сообщение с нового номера → в «Чатах» новый разговор с меткой «новый
   клиент» не позже 10 секунд; в «Клиентах» — клиент с меткой «из чата»; ушёл автоответ.
4. Симулятор: сообщение с номера существующего клиента → разговор привязан к нему,
   новый клиент не создан.
5. Менеджер отвечает текстом и фото → статусы «отправлено → доставлено → прочитано»;
   менеджер стал ответственным.
6. «Отправить QR» с суммой → картинка и текст в ленте.
7. Звук и всплывающее уведомление у второго сотрудника с открытой CRM; счётчик меню.
8. Сообщение «старше 24 часов» (подменить `last_inbound_at` в админке) → поле ввода
   закрыто с пояснением.
9. Флорист: пункта «Чаты» нет, прямой запрос к API разговоров → 403.
10. Неверная подпись вебхука → 401, событие не записано.
11. Ширина 390: список → разговор → назад.

Только после всех пунктов на сервере переключаем `TAPME_META_MODE=live` (в понедельник).
